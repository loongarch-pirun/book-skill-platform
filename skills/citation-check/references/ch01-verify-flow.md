# 核查动线：自检路与他查路

## 自检路（写完答案逐条过闸）

1. 答案里每条带〔出处〕的引文，逐条跑 cite_check(book, quote)
2. 命中 → 采用；返回的块号/章节/页码写进出处
3. 未命中 → 见 ch02 的四形态分流处理，**不要**降级为「大概齐」保留
4. 全部过闸才交付；答案里未标出处的观点句若依赖了库内容，补标或明确转为「我的推断」

## 他查路（外来引文验真）

别人给你的「书中原句」（文章引用、聊天记录、别的智能体的输出）：

1. 先 list_books 核对声称的书在不在库——库里没有的书无法核查，如实说「库外无从验证」，不许顺手放行
2. 在库 → cite_check 验原文；命中后核对**出处标记**（章节/页码）是否与返回一致
3. 产出核查报告：原句 → 命中状态 → 库内定位（块号/页码）→ 差异点（若有）

## 实测案例：出处标错 ≠ 引文造假（2026-10-21 第一手实测）

engineering-research 技能落盘时，Dynamo 引文本身逐字为真（「Thus, each node becomes responsible for the ring...」来自探针真实返回），但出处标成〔Dynamo·1〕——cite_check 报 **quote-not-found**，hint 给出「该章实文（前60字）：DynamoAmazonsHighlyAvailableKeyvalueStore...」（页 1 是标题页）。

**正确应对**：查库定位该句真实页码（`SELECT page FROM chunks WHERE text LIKE '%关键子串%'` → 页 6），改标〔Dynamo·6〕后回验通过。
**错误应对**：看到 quote-not-found 就把真引文扔掉；或反过来「引文是探针拿的肯定真」而绕过校验硬交。

**这条案例的教训**：cite_check 拒收只说明「声称的出处对不上」，真伪、错标、错字要按 ch02 的形态分流查——拒收是核查的起点，不是终点。
