# 验收七关：newbook-check + eval 双门 + 四本账

## newbook-check 七关（新书体检）

新书入库前后跑 `newbook-check`，七关依次为账实相符类的机械检查（书架 meta ↔ 库内实况 ↔ 磁盘文件三方对账）。**任何一关红都不许进书架**——账实不符的书会把后续所有检索评测变成噪音源。

## eval 双门（检索质量验收）

改了库内容（新书/清洗/重建）后跑全卷 eval：

- **双门**：分数 ≥ 基线 **且** 漏题 ⊆ 基线漏题——只看总分不设漏题门，会漏掉「新对了 3 题但错了 2 题旧题」的隐性回归
- 基线快照：2026-10-20 = 116/125 题 93 分（金卷 125 题）
- 纪律：**扩考卷先单题探针再进卷**（防坏题污染整卷）；rerank 开着跑半场约 5.9s/题，先估时长再排程
- 漏题溯源：结构型漏题（楼主长贴内具体论点）在检索层/查询改写找补，不在清洗层硬修

## 四本账同步（进书架前最后一步）

清洗/行级清洗/重建后：chunk_count、total_chars、total_tokens、chapter_quality 四本账与库内实况核对——`list_books` 返回的体量账要与 meta 实值一致（ch01 铁律 2）。

## 技能体检（书库增删后必跑，2026-10-21 上线）

`node src/check-skills.mjs`（或 MCP `check_skills`）对 skills/ 全部技能包出红黄绿报告：

- **红**（不可信不可用）：源书被删 / 引文回源失败 / 索引断链 / 覆盖声称对不上
- **黄**（能用但提醒）：源书被关（书还在，引文仍可回源）/ 无章节文件 / catalog.json 异常
- **绿**：全部通过。退出码 0=无红、1=有红（可串门禁）

为什么必须跑：`save_skill` 的三道质检只保**落盘那一刻**干净，保不了以后——书删了、重建了、章名变了，旧包的引文会悄悄烂掉。修法是智能体的活：`read_skill` 取全文 → 改 → `save_skill` 整包重交（三道质检重跑）。

## 实录案例 4：kb-research 引文腐烂（体检工具第一案，2026-10-21）

新工具上真库第一跑就逮到：kb-research 3 条引文断——两条章节名写成「客户端负载均衡›地域与区域」「网关路由›网络 I/O 模型」（早前从 get_outline 的层级显示抄的，库内实值是平名「地域与区域」「网络 I/O 模型」），一条是省略号拼接的转述非逐字。另顺带发现一条 `〔Dynamo〕` 无「·章节」——引文提取器只认「〔别名·章节〕」，这种写法整个绕过回源验证（补：`〔Dynamo·6〕` + sources 声明后 8/8 全过）。

**教训**：引文章节名必须是库内实值（`get_outline` 显示的层级路径 ≠ chunks 表里的 chapter 值）；「……」拼接的转述不是引文，逐字照抄才有回源意义。

## 实录案例 2：d2l 重建（语义分块教训的出处）

动手学深度学习：无语义分块 33323 块（碎片化，检索不可用）→ BSP_SEMANTIC=1 重建 5501 块。**判定信号**：入库后单书块数异常巨大（同类书 5-10 倍）≈ 语义分块没开——先查再重建，别调检索参数硬凑。

## 实录案例 3：编目验收（人名逐字预验）

编目导入五重校验中，人物 match_names **必须 instr 预验原文**——凭记忆写人名（如「芻狗」写成「鱼狗」）会被引文回验拦下。编目声称（N 主题/M 人物）用 `list_catalog` 实时返回核对，不凭记忆背书。
