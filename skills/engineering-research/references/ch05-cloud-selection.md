# 云选型参考：中文问不到 og-aws 的教训

## 动线

1. **英文问**——og-aws / system-design-primer / Dynamo 全是英文书，跨语言 embedding 双杀（中文问 → 正主根本不进路由窗口）
2. query_library 英文问题 → 路由到英文工程书 → 取原文
3. 引文照抄英文原文，cite_check 回验

## 实测案例：S3 选型（2026-10-21 探针第一手数据）

### 反例：中文问 AWS 问题——og-aws 消失了

**输入**：「AWS 生产环境的 S3 桶命名与安全最佳实践」

**输出**：路由给了凤凰架构(0.912)、系统设计入门(0.904)、Hello 算法(0.885)、动手学深度学习(0.879)——**og-aws（AWS 工程手册正主）根本没进前四路由窗口**。块级倒是从凤凰架构带出一段可用的 S3 特性内容（0.237）：

> S3 也许是 AWS 最出名、使用面最广的存储服务，这个结果不是由于它的性能优异，事实上 S3 的性能比起 EBS 和 EFS 来说是相对最差的，但它的优势在于它名字中"Simple"所标榜的简单〔凤凰架构·容器插件生态〕

**这段可用但不是 og-aws 的运维最佳实践**——问的是桶命名与安全，答的是 S3 特性定位。正确姿势：同一问题换成英文（「AWS S3 bucket naming and security best practices in production」）og-aws 才会进路由。

### 正例（参照）：Dynamo 英文问

「how does consistent hashing and replication work in Dynamo」——英文问英文书，路由 Dynamo(0.906) + 块级 0.946（见 ch03 案例 1）。

## 结论

**云选型/亚马逊工程实践类问题一律英文问**。中文问会路由到讲同一主题的中文书（凤凰架构这类），内容可用但永远拿不到英文书里的运维细节——而那正是选型参考的核心价值。
