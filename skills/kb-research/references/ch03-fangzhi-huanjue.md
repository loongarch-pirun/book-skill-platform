# 防幻觉铁律

## 三条红线

1. **引文必须逐字**：引用前 cite_check 验过；验不过的句子删掉或改写为「书中没有」。引用照抄工具返回（繁体照抄），行尾带〔书名·章节〕。
2. **没有依据就明说**：问题超出书库覆盖范围，明确报告「本书库中没有找到依据」，附上找过的路径（查了哪几本、用了什么问法）。**宁可少答，不可编造。**
3. **区分「书里说的」和「我推的」**：基于原文的推理可以给，但必须标注哪些是原文、哪些是推断；推断不给出处伪装成引用。

## 真实案例（第一手实测，非编造）

### 案例 1：超范围编造（凤凰架构 e2e 实测）

问「电商系统的订单库分片策略」——书里讲分布式事务、缓存、架构演进，但**没有订单库分片的具体策略**。正确的回答是：报告书中相关章节（分布式事务的定位与适用范围）+ 明确说分片策略本书没有展开 + 建议查什么。错误的回答是：顺着「分布式」三个字编一段分库分表方案——那是一删就穿的幻觉。

### 案例 2：块级漂移——路由对了，块不对（2026-10-21 探针实测）

问「用 Python 实现快速排序，给出代码示例」——路由对了（Hello 算法 0.902），但块级返回的是**堆的常用操作(0.820)、哈希表常用操作(0.790)、列表遍历(0.657)**——三块全不是快排。书里确实有快排章节，是检索没回到正主。

**正确应对**：不用这三块冒充答案；换问法（「快速排序」换「quick sort」）或 get_outline 直接翻排序章，把快排原文找出来再答。**错误应对**：拿 0.820 的堆操作块硬凑「排序相关的代码示例」——分数再高，内容不对就是不对。

### 案例 3：路由分高 ≠ 有依据（同一批实测）

同一问题四本书路由分 0.85-0.91 挤在一起，只能说明「这些书都在讲系统设计」——**不代表书里有你问的那个具体方案**。路由分是书的资质，原文才是依据；两者之间必须隔一次 cite_check。

## 为什么值得
知识库的价值 = 可信的锚。一次编造被抓住，整个库的可信度都受损；每次「书中没有」都明说，智能体的结论才敢被拿去定架构、写方案。
