### 1.1 预筛的取舍（这一条最关键）

**只认一种信号：问句里点了书名。** 原名、美化名、锚点、中文别名都算。

```
selectBooks(q, books)
  ├─ 命中 ≥1 本 → targetBooks = 命中的书，route_source:"prefilter"
  ├─ 命中 0 本   → targetBooks = 全库，      route_source:"full"（旧行为）
  └─ 预筛的书一本都没扫成（全坏库/全 build-only）→ 重扫全库，route_source:"degraded"
```

**为什么不做「按向量粗筛」或「质心预筛」**：那等于把第一段扫描换个地方重跑，而且会引入新的漏召回。纯字面判断零成本、零猜错风险。

**明确的能力边界**：问句不点书名（"who tries to separate jane and bingley"、"At which church was the wedding"）→ 预筛不生效，仍扫全库。这类问题**没有提速**，但也不受影响。真正的提速要等 P2（缓存）与后续的目录信号。

| 对照 | 口径 | 结果 |

那 2 题的差异原文：

```
「弗兰肯斯坦在哪个城市读大学」
  改造前: routed = [frankenstein, pride-and-prejudice]
  现在  : routed = [frankenstein]
```

**原因**：预筛没扫的书拿不到书级信号，自然不会进挑书清单。**这不是退化，是预筛的必然结果**——没翻的书不该出现在「我翻了这几本」里。答案内容逐题一致。

## 4. 收益与代价

**拿到**：
- 命名书名的提问：扫描本数 13 → 1（`route_source:"prefilter"`），单题耗时随之下降；
- 整体留出集平均耗时 −27.3%；
- 三个开关全部**默认即旧行为**，可一键回退。

**代价 / 边界（如实写）**：
- 不点书名的提问零提速；
- 挑书清单在预筛路径下会变短（答案不受影响）；
- `selectBooks` 是字面匹配，同一本书若书名与问法完全无交集（如「第一章里出现的那个人名」）不会命中，仍走全库。

**仍未做**：
- 向量矩阵缓存对路由扫描仍未生效（P2）；
- `stage3-mcp-test` / `perf-test` 未在本轮跑（依赖真实 MCP 与 10 本复制库，留给 E/F）。
