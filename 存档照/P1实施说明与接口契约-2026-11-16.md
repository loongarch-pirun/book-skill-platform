## 1. 现有路由结构（改造前基线）

项目里其实有两条检索路径，只有一条受本次改动影响：

| 路径 | 入口 | 扫描范围 | 是否受影响 |
|---|---|---|---|
| 单书问答 | `hybridSearch(dbPath, q, topN)` `search.mjs:212` | 只开一本书 | **否**（一行未动） |
| 全库自动挑书 | `routeAndSearch(q, {topN, maxBooks, libDir})` `search.mjs:651` | 全库 | 是 |

### 1.1 三段式（`BSP_ROUTE=0` 时仍逐字节走这一条）

```
listBooks(libDir)                      ← L1 缓存，12 字段/本
   │  books = 13 本
   ▼
【第 1 段】for (const b of books)      ← 串行、无条件、全库
   scanBookSem(b.db)  :545
     ├ new Database(readonly) → PRAGMA → 无 emb 早退
     ├ assertEngine(db, embedKey)      ← 引擎卫兵，必须在最前
     └ SELECT id,kind,length(text),emb → 逐行读 BLOB → cosine → rows.sort(余弦降序)
   bookSignal(rows)   :573  → 合格块前 3 条余弦均值 = 书级信号 sig
   considered.push({title, best_sim, n})   ← 「翻了哪些书」的全量清单
   │
   ▼
【第 2 段】scanned.sort(sig) → slice(0, 8)
   tightPick(每本 rows, 10)  :565 → 碎片门槛 minLen=60
   → pool → 去重 → 按 sem 排序 → 截 48 条
   attachChunks(48)  :626 → 补 text / loc / kind（只查进池的几十条）
   │
   ▼
【第 3 段】唯一一次 rerank（逐条串行 ≈128ms，48 条 ≈6s）
   rank = rerank × (kind==="ref" ? 0.5 : 1)
   byBook 聚合 → bookScore = 0.5×该书最好一条 + 0.5×(sig / sigMax)
   floor = bestMax × 0.3 → picked = 书分 ≥ floor 的前 maxBooks 本
   results = 入选书的块，先按书序、书内按 rank → slice(0, topN)
   │
   ▼
{ routed_books, considered, results, [skipped_books], [ambiguous] }
```

**改造前的成本结构**：余弦总次数 = Σ(全库 13 本的块数) ≈ 5,844 次 BLOB 读 + 5,844 次 1024 维点积，**每问一次**。第 9 名以后的书付了全部代价却被 `slice(0, 8)` 截掉，零新增候选。

## 3. 改造后的目标行为

### 3.1 分支矩阵（`selectBooks` 决策）

| 条件 | `targetBooks` | `route_source` | 行为等价性 |
|---|---|---|---|
| 问句里命中书名/别名 **≥1 本** | 命中的书 | `"prefilter"` | 扫得少；挑书清单可能变短 |
| 问句里 **0 命中** | 全库 | `"full"` | **逐字节等于改造前** |
| 预筛命中但**一本都没扫成**（全坏库/全 build-only） | 退回全库重扫 | `"degraded"` | 结果同 full；源头已换，单独记账 |
| `BSP_ROUTE=0` | 全库 | `"full"` | **逐字节等于改造前**（`selectBooks` 一次都不调用） |

### 3.2 命中信号（零模型、零向量、零开库）

| 信号 | 来源 | 例 |
|---|---|---|
| 原始标题 | `listBooks().title` | `Dynamo-亚马逊高可用键值存储-2007` |
| 美化标题 | `prettyTitle()` `:139` | `pg1260-简爱` → `简爱` |
| 锚点 | `anchorsOf()` `:156` | `MapReduce`、`attention`、`Dynamo` |
| 中文别名 | `BOOK_ALIAS`（14 条） | `daodejing→道德经/道德經/老子`、`lunyu→论语/論語`、`pg1661→福尔摩斯/sherlock/holmes` |

长度下限 3 字符；匹配方式为**小写子串包含**。

### 3.3 保留不变的核心算法

第 2 段的「书级信号排序 + 每本取 10 条 + 池子截断」、第 3 段的「一次性统一重排 + 参考文献降权 + 0.5/0.5 书分 + 相对门槛 0.3 + 书序即答案序」**全部原样保留**。本次只改「第 1 段扫谁」，不改「怎么打分」。

## 4. 接口约定

### 4.1 入参（签名未变）

```js
routeAndSearch(question, { topN = 4, maxBooks = 4, libDir = currentLibDir() } = {})
```

### 4.2 返回体

**原有 5 个字段结构一格未改**（`routed_books` / `considered` / `results` / `skipped_books` / `ambiguous`），字段含义、类型、排序规则全部保持。

**新增 2 个诊断字段**（纯加法，老调用方忽略即可）：

| 字段 | 类型 | 含义 |
|---|---|---|
| `route_source` | `"prefilter" \| "full" \| "degraded"` | 这次为什么扫这些书 |
| `route_candidates` | `string[]` | 实际进入第 1 段扫描的书名 |

### 4.3 配置开关（全部「默认即旧行为」）

| env | 默认 | 语义 | 是否真开关 |
|---|---|---|---|
| `BSP_ROUTE` | 未设 = 开 | `=0` 关总闸，回到全库扫描 | ✅ 每次调用现读 |
| `BSP_ROUTE_POOL` | 未设 = 48 | `=auto` 用动态配额；数字 = 固定条数（上限 48） | ✅ |
| `BSP_ROUTE_MINLEN` | 60 | 碎片门槛 | ✅（改造前是顶层 const，是假开关） |
| `BSP_ROUTE_BOOKS` | 8 | 第 2 段深召回几本书 | ✅ |
| `BSP_ROUTE_K` | 10 | 每本深召回几条 | ✅ |
| `BSP_ROUTE_REFW` | 0.5 | 参考文献降权系数 | ✅ |
| `BSP_RERANK_BUDGET_MS` | 6000 | 仅 `BSP_ROUTE_POOL=auto` 时用于算配额 | ✅ |

**默认值契约**：`ROUTE_DEFAULTS` 七项（`60/3/8/10/0.5/48/0.3`）逐字等于改造前，由 `guard-test` 静态断言钉死。

### 4.4 复杂度

| | 改造前 | 改造后（prefilter 命中） | 改造后（full） |
|---|---|---|---|
| 开库次数 | N | min(k, N) | N |
| BLOB 读 + 余弦 | Σ_{b∈全库} C_b | Σ_{b∈候选} C_b | 同改造前 |

## 9. 与定稿的偏差（逐条说明）

| # | 定稿写的 | 实际实现 | 为什么 |
|---|---|---|---|
| 1 | 「候选书 < 3 本退回全库」 | 改成「命中 0 本才 full；命中 ≥1 本即用」 | 13 本书里，一个问句通常只点 1 本书名。按 <3 退回等于预筛永不生效（实测覆盖 0%）。风险用「降级重扫」兜住 |
| 2 | 降级链 5 档（无清单/孤儿/指代/空候选） | 实现 3 档：`prefilter` / `full` / `degraded` | `catalog-results/*.json` 的文件名与 13 本 .db **对不上**（如 `jane-eyre-en.epub.json` vs `pg1260-简爱.epub.db`），别名映射只存在于 `test/lib/book-alias.mjs`（测试目录）。生产码引用测试目录会破坏分层，故本轮不接清单信号，留作后续 |
| 3 | 静态断言 6 条 | 实现 7 条 | 多一条「`assertEngine` 必须先于 `getMatrix`」——为 P2 提前上锁 |
| 4 | 诊断字段 2 个 | 一致 | — |
| 5 | 不新增 `src/` 文件 | 一致（全部内联进 `search.mjs`） | — |

**偏差 2 的后果必须说清**：不接目录信号 ⇒ 问句不提书名时预筛失效。这是本轮收益的主要天花板（留出集 30 题里约 11 题走 `full`）。
