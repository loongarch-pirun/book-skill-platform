## 3. 审查意见

### 🔴 Blocker 1 · 契约：新增的返回字段零保护

`src/lib/search.mjs` 返回体新增 `route_source`、`route_candidates` 两个字段，但**全仓库没有任何测试引用它们**：

```
grep -rn "route_source|route_candidates" test/   →   0 命中
```

**为什么是 Blocker**：这两个字段是「这次扫了几本、为什么这么扫」的唯一对外说明。它们没有任何调用方强制依赖，所以：
- 谁哪天顺手删掉，编译不报错、340 条断言全绿、卷子分数不变；
- 而排查线上「为什么只翻了一本书」时，就再也看不到答案了。

按本仓库自己的标准（§4 红线 1「改返回字段结构」），新增字段必须同时新增保护，否则等于埋了个静默退化点。

**建议**（3 行，加进 `guard-test.mjs` 路由段）：

```js
const out = await routeAndSearch("《道德经》第十五章开头用哪两个词", { libDir, topN: 1 });
ok(typeof out.route_source === "string" && ["prefilter","full","degraded"].includes(out.route_source),
  `路由: route_source 存在且取值受控（${out.route_source}）`);
ok(Array.isArray(out.route_candidates) && out.route_candidates.length >= 1,
  "路由: route_candidates 是非空书名字符串数组");
```

### 🟡 Suggestion 1 · 一个批次塞了四个不相干主题

32 个文件里混着：P1 路由、P2 缓存、旧 eval 体系移除、文档纠偏、审查机制新增。**出问题要 revert 时无法只退一个。** 建议按主题拆 4 个提交，`tools/` 与 `docs/` 可以走 A/B 级不占审查额度。

### 🟡 Suggestion 2 · `selectBooks()` 仍无单元测试

它现在只被静态断言（存在性 + 定义顺序）和独立卷子**间接**覆盖。三分支里「预筛全失败 → 退回全库重扫」这条**在真库上很难触发**（要 13 本全是坏库），等于没验过。
建议补一个小测试：书名命中（1 本）/ 零命中（全库）/ 强制坏库（降级）三分支各一条。

### 🟡 Suggestion 3 · `npm run holdout` 不在任何测试档里

`package.json` 加了入口，但 `test:ci`/`test:fast`/`test:slow` 都没挂它。靠人记着跑的东西，三个月后一定没人跑。建议把 `node test/holdout-run.mjs --gate` 挂进 `test:slow` 末尾（它在有模型的本机能跑，CI 无模型本来就不跑 slow）。

### 💭 Nit 1 · `size-budget.json`、`docs/真机验收勾选单.md` 来源待确认

## 5. 流程自身的缺陷（如实登记）

1. **作者 = 审查人，违反 C 级规定。** 本次是流程演练，没有第二个人。真实使用时 C 级改动必须换人——否则这套机制的价值会退化成"自己给自己盖章"。
2. **关 4 的效果验收这次只跑了 v1 门禁**（27/30）。严格按标准应同时跑「现行 vs 对照组」差分——那个已经在 `P3` 报告里做过（v2 卷 26/30 vs 26/30，逐题一致），本批没有新改检索打分逻辑，所以没重跑。
3. **没有「第二次审查」的机制。** 如果作者补完 Blocker 又顺手改了别处，没人会再看一遍。建议：补 Blocker 的改动只许动断言段，动了别处重新走一遍。
