**起草阶段一次检索都没跑。** 证据链：

3. `回源验真.cjs` —— 直接开 13 个真库，按 `(bookId, chunk_id)` 查回原文，验证 `a` 是 `chunks.text` 的子串、金词至少一个命中；

**没有跑过任何一次「这题能不能命中」的探针。** 老卷那套「先探针实跑再入卷」的做法，正是不可证伪的根因，本卷方向相反。

## 4. 字段说明

每题：`{id, q, book, bookId, kind, a, g, expect, lang, hasTopicJson, chunk_id, source}`。

- `bookId` = `library/*.db` 真实文件名前缀，不用别名，防止书名改动后静默丢题；
- `a` = 该块 `text` 的前 260 字连续片段（**不是**完整句，可能停在半句）；本卷按方案改用 `g` + `cite-check` 回源判分，不强依赖整句完整，但已逐题确认关键答案句都在片段内；
- `g` = 金词，判分用 `some` 语义（命中任一即有效题）；
- `expect` = `refusal` / `ambiguous` / `null`；
- `hasTopicJson:false` 专用于验「新书没有主题清单时的降级路径」；
- `source.frozenAt` 与 `reviewedBy` 现为 `null`，**冻结时统一补齐**。

## 5. 老实说清的边界

1. **仍是自方出题**。独立性不靠「题目权威」，靠「先冻结、后实现、出题时看不见分数」＋ 留出集 ＋ 对照组。这一条不假装成第三方盲测。
2. **12 道无答案句题还没有判分器**。`judgeRefusal()` 与歧义判据要等 Phase 1 建 runner 时实现；拒答不能靠「分数低就算合格」，必须配合引用回源或明确阈值。
3. **8 道拒答题「库里确实没有」是人工判断**，需要爸爸复核时逐条确认；自动验真只覆盖了有答案句的 18 题。
4. **4 道歧义题的「歧义」也是人工判断**，复核时请确认是否真的多书可答。
5. **答案句取自单块 260 字连续片段**，若以后重切块或老书重建，本卷要按 `content_hash` 重验（方案 `recheck.mjs` 的职责）。
