# 恢复手册：换电脑 / 重装系统后重建 book-skill-platform

> 适用场景：换新电脑、重装系统、硬盘故障后重建。
> 核心思想：**你真正需要带走的只有一个备份文件夹**（约 30~35MB），其他一切都能重建。

---

## 一、平时怎么备份（一分钟）

```bash
npm run backup
```

脚本会自动做四件事：

1. 把 `library/*.db` 做一次 WAL checkpoint（保证拷出去是完整一致的库文件）
2. 生成 `repo.bundle`（全部代码 + git 历史打包成单文件，可直接 clone）
3. 写 `MANIFEST.txt`（本次备份清单 + 恢复提示）
4. 清理旧备份，默认保留最近 3 份（`--keep N` 或环境变量 `BSP_BACKUP_KEEP` 可调）

**关键一步：备份完成后，把 `backup/bsp-backup-<日期>/` 整个文件夹拷到项目外**（U 盘 / 网盘）。备份躺在同一块硬盘上等于没备份。

**备份节奏建议**：每编完一批新书跑一次；至少每周一次。

## 二、备份里有什么

| 文件 | 是什么 | 丢了会怎样 |
|---|---|---|
| `*.db`（6 个） | 书库唯一真身：向量 + 全文 + 编目 + 引用源 | **无法重建**（要重灌重编目） |
| `repo.bundle` | 全部代码 + 12+ 条 git 提交历史 | 可由其他副本重建，但历史丢了 |
| `MANIFEST.txt` | 备份清单与恢复提示 | 无关紧要 |

不备份的：`node_modules/`（`npm install` 重建）、`.models/`（约 2.7GB，首次使用时自动从 hf-mirror 重下）、`release/`（打包产物）。

## 三、新机器重建步骤（约 15 分钟，大头是下载）

前置：装好 **Node 22+**（nodejs.org）和 **Git**。

```bash
# 1. 从备份的 repo.bundle 克隆全部代码（注意路径指向备份文件夹）
git clone <备份文件夹>/repo.bundle book-skill-platform
cd book-skill-platform

# 2. 装依赖（better-sqlite3 有预编译包，一般 1~3 分钟）
npm install

# 3. 把备份里的 *.db 拷回项目 library/（目录不存在就新建）
mkdir library
cp <备份文件夹>/*.db library/

# 4. 全套验收（10 套测试应全绿；过程会按需自动下载模型，走 hf-mirror，几分钟）
npm test
```

验收标准：

- `npm run test:fast`（guard / stage0 / stage1 / ftsliteral / catalog / skill-store）秒级全绿
- `npm run test:slow`（stage2 / stage3 / perf / eval-gate）首次会触发模型下载：
  - e5 嵌入模型 112MB + m3 复试官 int8 574MB → 缓存到项目 `.models/`
  - eval-gate 两道硬门：**≥ 88 分** 且 漏题 ⊆ 基线漏题（锚点在 `test/eval-baseline.json`）

```bash
# 5. 起 MCP 服务做最终确认（应打印 7 个工具 ready）
npm run mcp
```

## 四、常见坑

1. **`.db` 与 `-wal` 要成对拷**：`npm run backup` 已做 checkpoint，正常只有 `.db`；
   如果是手工拷贝且库里还有 `-wal` 文件，必须一起拷走，少了 wal 会丢最后一段写入。
2. **引擎一致性卫兵**：检索相关测试红时，先确认模型下载完整（`.models/` 里 e5 与 m3 都在），
   两端引擎不一致会被 `assertEngine` 直接拒跑——这是防线，不是故障。
3. **书库文件名不能改**：书 id 与 `.db` 文件名绑定（如 `daodejing-zh.docx.db`），改名等于换书。
4. **中文书是繁体**：金标准与搜索验证一律用书中原字，别自行简转繁。
5. **clone 自 bundle 后**，`origin` 指向的是 bundle 文件路径，属正常现象；
   以后想推 GitHub，`git remote set-url origin <github 地址>` 即可。
