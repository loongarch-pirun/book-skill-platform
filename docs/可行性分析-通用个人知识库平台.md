# 方案可行性分析（v1.3）

> 分析人：项目总监（基于架构师联网核实证据 + 方案 v1.3 全文）
> 结论先行：**可行，无致命阻塞。有 3 个非致命不确定点，都安排了实测和止损方案。**

---

## 一、总体结论

| 维度 | 结论 | 信心 |
|------|------|------|
| 技术可行性 | 每个零件都有成熟实战，无一需要"发明新东西" | ★★★★☆ |
| 环境可行性 | 普通家用 Windows 电脑就能跑，无需显卡、无需 API key | ★★★★★ |
| 工期可行性 | 全程 AI 开发，约 8~10 个工作日出安装包 | ★★★★☆ |
| 人的可行性 | 老板零代码，角色只有"提需求+验收"，客户端保证看得见摸得着 | ★★★★★ |

**一句话：这是一个"组装成熟零件"的工程，不是科研攻关。风险不在"能不能做出来"，在"做出来好不好用"（见第四节三个不确定点）。**

## 二、技术可行性（逐零件，附核实证据）

| 零件 | 成熟度 | 依据 | 残留风险 |
|------|--------|------|----------|
| PDF 按页提取（pdfjs-dist） | 高 | Mozilla 维护，纯 JS，逐页文本层提取是它的看家本领 | 扫描版无文本层（已在不做清单） |
| DOCX 提取（mammoth） | 高 | 成熟库，提纯文本+标题层级 | 无 |
| EPUB 解析（自研） | 中 | epub 物理上就是 zip + XHTML，难度不高但**边角情况多**（加密 epub、畸形目录） | 预估 1 天内；加密 epub 明确不支持 |
| SQLite + trigram 中文检索 | 高 | better-sqlite3 内置 SQLite 3.50.4、FTS5 编译选项齐全，Windows 免编译；trigram 是 SQLite 官方特性 | <3 字符查询需降级 LIKE（已知解法） |
| 中文向量（bge-small-zh + transformers.js） | 中高 | Node 本地跑 ONNX 有成熟实战，模型是中文向量化事实标准 | **中文书实际检索效果需实测**（阶段2 验收） |
| 向量检索（纯 JS 余弦） | 高 | 单书几千~几万块，毫秒级暴力计算足够 | 书超大规模才需升级（个人用达不到） |
| 规则图谱（零 LLM） | 高 | 纯确定性规则（目录树+关键词共现+相似段落），可测试、可复现 | 关联质量不如 LLM 抽取（MVP 够用，v2 可升级） |
| MCP skill（官方 TS SDK） | 高 | 官方维护，stdio/http 双通道，与 Electron 同栈 | 无（stdout 日志坑已写进 Spec） |
| Electron 打包（electron-builder） | 中高 | 最主流方案；better-sqlite3 需 electron-rebuild，社区方案齐全 | 原生模块偶发编译坑 → **阶段0 就打一个最小 exe 验证掉** |

## 三、环境与资源可行性

- **CPU/内存**：向量检索峰值约 20MB 内存、SQLite 按需读切片——十年前的电脑都够
- **显卡**：不需要（图谱零 LLM、向量模型是 CPU 跑的小模型）
- **磁盘**：向量模型约 50MB + 每本书一个 .db（几百 MB 级别）——无压力
- **网络**：只在首次下载向量模型时需要（走国内镜像），之后完全离线
- **费用**：0 元。无 API key、无订阅、无云服务
- **老板要做的**：提需求 + 每阶段验收点个头

## 四、三个诚实的不确定点（唯一可能"不好用"的地方）

| # | 不确定点 | 为什么不确定 | 止损方案 |
|---|----------|--------------|----------|
| 1 | **中文检索质量能否让你满意** | 技术上"能搜到"已验证，但"搜得准不准"是主观体验 | 阶段2 结束拿真实问题试问，不满意调参/换模型，方案留了备选 |
| 2 | **总入口自动挑书的准确率** | 问跨书问题时挑错书 = 答非所问 | 先按"书描述匹配+向量相似"路由，错挑可手动指定书重问（客户端留手动指定入口） |
| 3 | **epub 边角情况** | 市面 epub 质量参差 | 测试书选规范公版书；畸形文件明确报错不崩 |

| **合计** | | **约 8~10 个工作日**（±2 天浮动） |

## 六、明确不可行 / 已放弃项（防有人再提）

- 扫描版 PDF（需 OCR）——不做
- LLM 图谱抽取（本地跑不动）——v2 可选
- 移动端 / 账号系统 / 多端同步——不做
- 让模型"吃下整本书"或压缩摘要——违背核心，不做

## 七、最终判定

**GO（放行开工）。** 前提条件：阶段0 的三件事实测通过（中文搜索、PDF 按页切、最小 exe 打包）——这三件事半天~1 天就有结果，是整个方案的"试金石"，任何一件失败都会在最早时间暴露，不会等到最后才炸。
