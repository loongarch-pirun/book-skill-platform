# 外部智能体接入文档：book-skill MCP（17 工具 + kb-research 动线）

> 给谁看：任何支持 MCP 协议的智能体（Claude / CodeBuddy / 自建 Agent…）接入本知识库时的操作说明书。
> 目标只有一个：**回答带库内原文论证，引的每句话都能逐字回源，找不到就明说。**
> 本文自包含——不需要读仓库里其他文档就能接入和使用。

---

## 一、30 秒接入

本知识库以标准 MCP stdio server 暴露（server 名 `book-skill`，入口 `src/mcp-server.mjs`）。在客户端的 MCP 配置里加：

```json
{
  "mcpServers": {
    "book-skill": {
      "command": "node",
      "args": ["<仓库绝对路径>/src/mcp-server.mjs"]
    }
  }
}
```

两个要点：

1. **库目录定位**：默认用仓库内 `library/` 目录（与启动 cwd 无关，绝对路径启动即可）。书库迁过位置的用户加环境变量：

```json
"args": ["<仓库绝对路径>/src/mcp-server.mjs"],
"env": { "BSP_LIB_DIR": "C:/Users/你/AppData/Roaming/BookSkillPlatform/library" }
```

2. **stdout 只走 MCP 协议**：server 的日志全部走 stderr，客户端不需要特殊处理。

**接入自检**（30 秒确认通了）：调一次 `list_books`——返回书数应等于库目录里 `.db` 文件数（≥1），每本带 `title / format / chunk_count / total_tokens / chapter_quality`。空返回时看第八节「已知坑」第 1 条。

## 二、17 个工具总表

按用途分六组。所有 `book` 参数都是**书名或书名片段**（大小写不敏感的子串匹配，如 `pride`、`论语`、`lunyu`）；书名没匹配上时不报错——检索类工具会自动路由到最相关的书并在 `note` 里说明。

### 导航组（先看有什么）

| 工具 | 参数 | 一句话 |
|---|---|---|
| `list_books` | — | 书架清单：每本带块数、≈token 总量、章节质量（reliable/messy/none）。**任何任务先调它**，按 total_tokens 决定读法 |
| `get_outline` | book, maxChapters≤500 | 全书地图：每章章名/块数/≈token/起始块号，附质量标记。PDF 报 no-chapters，EPUB 章名不可靠标 messy |
| `list_skills` | — | 已落盘技能清单。**回答任务前先看有没有现成手册**——有就不必重新检索全书 |

### 检索组（查「哪段讲了 X」）

| 工具 | 参数 | 一句话 |
|---|---|---|
| `query_book` | book, question, topN≤20(默认4) | 单书检索：结果带页码（PDF）或章节（epub/docx）定位，原文一字不改 |
| `query_library` | question, topN, maxBooks≤8(默认4) | 全库检索自动挑书：不知道查哪本时用；结果带书的归属和定位 |
| `similar_chunks` | book, chunk_id 或 text, topN | 以块找块：「这段话还有哪里讲过类似的事」。chunk_id 入口最快（纯库内余弦） |
| `lookup` | book, key, maxBlocks≤40(默认20) | 章节直达：错误码/条款号/步骤标题的精确寻址（三级匹配） |

### 原文组（把内容完整读进来）

| 工具 | 参数 | 一句话 |
|---|---|---|
| `read_full_book` | book | ≤10K token 小书全文直读（超限返回 too-big 并给体量与指路）。小书走检索是纯损耗，全文进上下文零检索误差 |
| `get_chapter` | book, chapter, maxBlocks≤60 | 按章名整章通读：token 闸 8K，截断时 note 带真实 token 账与续读块号 |
| `read_range` | book, from, to, maxBlocks≤80 | 按块号区间连续读（from/to 是其他工具结果里的 id）。PDF / messy EPUB 的首选 |

### 编目组（人物/主题的结构化地图）

| 工具 | 参数 | 一句话 |
|---|---|---|
| `list_catalog` | book, theme? | 编目浏览：主题分区 + 人物表 + 人物关系网。人物关系类问题**先看这里**再查原文 |
| `get_person` | book, name | 人物深查：身份、书中写法、出场块数、关系边、代表原文块 |
| `get_theme` | book, name | 主题深查：主题说明、覆盖块数、章节分布、代表原文块 |
| `expand` | book, name, perNeighbor≤5 | 关系网邻域：顺着关系边拉出邻居（「还有谁牵涉其中」） |

### 技能组（智能体可自建手册）

| 工具 | 参数 | 一句话 |
|---|---|---|
| `read_skill` | slug, chapter? | 按需加载技能：不带 chapter 只回 SKILL.md + 章节索引（含每章 token），**先看索引再读章** |
| `save_skill` | slug, files[] | 技能落盘（整包幂等覆盖）：结构校验 + **引用回源验证**——blockquote 里「〔书名·章节〕」引文会到 library 逐字比对，造假整包拒收 |

### 质检组（防幻觉最后一关）

| 工具 | 参数 | 一句话 |
|---|---|---|
| `cite_check` | book, quote | 引文回验：命中返回块号/章节/页码；**未命中明确告知不要采用** |

## 三、标准动线：kb-research 五步

> 本仓库内嵌了完整操作规程技能 `kb-research`（可用 `read_skill` 加载），这里给主干。

工作需要一个依据时，按这五步走：

1. **`list_books`** —— 看书架：有哪些书、每本 ≈多少 token、章节质量。
2. **按体量分流** —— ≤10K token 用 `read_full_book` 全文直读；>10K 用 `get_outline` 看全书地图。
3. **定位板块读原文** —— `get_chapter` 按章名通读 / `read_range` 按块号读；查具体问题 `query_book` 兜底；人物/主题类先 `list_catalog` 看结构化地图。
4. **`cite_check` 自检** —— 引文贴回去验：命中才采用，未命中不要采用。
5. **没有就明说** —— 库里没有依据的，明确报告「书中没有」，不许编造。

### 场景速查

| 场景 | 动线 |
|---|---|
| 「根据库里内容定方案」 | list_books → 相关书 get_outline → get_chapter 读关键章 → cite_check 验引文 → 明说没覆盖的部分 |
| 「这本书讲了什么」 | ≤10K read_full_book；>10K get_outline + 挑 2-3 章 get_chapter |
| 「X 在书里哪里提到」 | query_book 定位 → get_chapter/read_range 取上下文 |
| 「人物关系类问题」 | list_catalog 关系网 → get_person/expand 摸到原文块 → query_book 取全文 |
| 「查错误码/条款号」 | lookup 精确直达（概念类才用 query_book） |
| 「PDF 里翻某段」 | read_range 按块号（PDF 无章节） |
| 「同类工作以前做过吗」 | list_skills → read_skill 按需加载章节 |
| 「蒸馏出一份新手册」 | save_skill 落盘（引用必须过回源验证） |

## 四、返回字段怎么读

所有工具返回 JSON（`content[0].text`），高频字段：

- **检索结果**（query_book / query_library / similar_chunks）：`results[].text` 原文、`results[].loc` 定位（PDF 页码 / epub 章节）、`results[].id` 块号（喂给 read_range / similar_chunks 用）、`results[].book` 归属。query_library 额外带 `routed_books[]`（每本 `best_sim` 相似度）。
- **token 账**（list_books / get_outline / get_chapter 截断 note）：`total_tokens` / 每章 `tokens` 是估算值（中英混合书按 CJK 占比分尺），用于**决定读法**，不是精确计数。
- **章节质量三态**（chapter_quality / get_outline 的 quality）：`reliable` 章名可信可按名翻章；`messy` 章名可能是正文片段、按名落空就用 read_range；`none` 无章节（PDF 类），直接 read_range/query_book。
- **错误与降级**：书名未命中返回 `{error, available}`（带书目清单）；read_full_book 超限返回 `{code:"too-big", ...指路}`；区间为空返回本书块号范围。**没有 throw——照着返回里的提示换参数即可。**

## 五、防幻觉铁律（不可协商）

1. **原文照抄**：引文从工具返回的 `text` 里复制，繁体照抄（勿自行简转繁），一字不改。
2. **引文必带出处**：行尾加〔书名·章节〕；出处来自工具返回的 `loc`/`chapter` 字段，不凭记忆写。
3. **`cite_check` 是最后一关**：写完带引用的答案，把引文贴回去验；未命中就删掉或改写为转述并明说。
4. **没有就明说**：库里查不到依据时，回答里明确「书库中没有相关内容」，可建议外部来源——**绝不编造**。
5. **检索结果 ≠ 全书观点**：topN 只是相似度最高的几块，下结论前尽量翻章核对上下文。

## 六、技能机制（让经验沉淀下来）

- 库里的 `skills/` 目录存着已蒸馏的技能包（SKILL.md + chapters/ + glossary/cheatsheet），如 `kb-research`（本动线的完整版）、`daodejing` 等。`list_skills` 看清单，`read_skill` 按需加载——**章节文件不读不占上下文**。
- 完成一次高质量查证后，可以把方法论蒸馏成技能包 `save_skill` 落盘，下次同类任务直接复用。落盘有三道质检，其中**引用回源验证**会到 library 逐字比对——引文造假整包拒收并指出位置。

---

## 七、性能预期

- 检索（query_book/query_library）：复试官（reranker）开启时单题约 3~6 秒；`BSP_RERANK=0` 环境变量可关掉（更快，召回质量降，仅供诊断）。
- read_full_book / read_range / 编目组：纯 SQLite 读取，毫秒级。
- 服务端进程内缓存书架清单（书架变化自动失效）；进程启动后首次调用稍慢（加载模型）。

---

## 八、已知坑与边界（接入前必读）

1. **`list_books` 返回 0 本 ≠ 库是空的**：书架上每本书有独立的 H3 开关（`<库目录>/skill-state.json`），用户关掉的书 MCP 也查不到。全空时先确认库目录指对了（BSP_LIB_DIR），再确认没有书被关掉。
2. **PDF 类书没有章节**：`get_outline`/`get_chapter` 报 no-chapters，用 `read_range` 按块号读或 `query_book` 检索。
3. **EPUB 章节名可能是正文片段**（质量标 messy）：按名翻章可能落空，`read_range` 是保底。
4. **英文书必须英文问**：跨语言检索双杀（向量空间分开 + 语义拉平），福尔摩斯/简爱/og-aws 等英文书用英文问题查。
5. **书名片段可能匹配多本**（如 `lunyu` 匹配 PDF+DOCX 两版）：工具会选第一本并在 `note` 里列出其余，要指定版本就用完整书名。
6. **topN 上限 20、maxBooks 上限 8**：模型一次索要 999 条会被 zod 拒收——分多次调或调大 maxBooks。
7. **token 账是估算**：用于分流决策（读全文还是翻章），不要当精确值引用。
8. **书架是动态的**：本文不写死书架规模，一切以 `list_books` 实时返回为准。
9. **工具清单以协议为准**：接入后 `tools/list` 返回 17 个工具；若与本文第二节对不上，以服务器实际返回为准并检查客户端缓存。
