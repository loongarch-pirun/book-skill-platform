## 裁决理由与后续条件

**链 A 暂缓升级**：electron-builder 是构建期工具，风险面不在用户机器上。升级 26.x 会动摇打包产物基线（files 过滤规则、asar 结构、图标链路），必须整套打包三层验收重跑——这件事本身就要排在所有代码修复定稿之后（现在升级等于把基线改两次）。触发条件：下一个桌面大版本周期，或出现 high/critical。

**链 B 暂缓 + 硬条件**：mammoth 是运行时依赖（build-book 解析 docx 走它），理论上不可达（argparse 不碰文件内容），但 mammoth 的修复版本是破坏性 API 变更，**现在升级会污染 P1 畸形 docx fuzz 的测试基线**。硬条件：P1 parser-fuzz 定稿之后，再在隔离分支试 mammoth@0.3.29；升级后必须重跑 parser-fuzz + 全套 12 套；若 API 不兼容导致 docx 解析回归，保持现版本，把「不可达分析」写进本文件结案，不再翻。

**监控线**：每次结题/大版本前重跑 `npm audit`；一旦出现 high 或 critical，不计代价立即升级并全套验收。
