# 项目方案：通用个人知识库平台（把书变成 skill）

> 版本：v1.3（2026-10-12）
> 来源：项目交接文档 + 老板确认（测试书用公开免费书；skill 走标准 MCP，任何智能体都能用；**最终形态 = 桌面安装包客户端**；本方案确认后再动手）
> 一句话目标：**一个装在电脑上的桌面软件——书拖进去变成可查的知识库，AI 通过 skill 来查，回答带页码、能翻回原文。**

---

## 一、这个工具是干嘛的（四步，缺一不可）

1. **输入**：书进来（pdf / epub / docx，文字版优先）
2. **能找**：书切成一小块一小块，**原文一字不改**，每块带页码，建好索引
3. **能调**：每本书打包成一个标准 skill（MCP 格式），任何智能体都能接
4. **有价值**：AI 干活时自己调用，回答带页码、能翻回原文核对 → 少编瞎话

## 二、最终形态：一个桌面客户端（"一个引擎，两张脸"）

**做出来是一个双击安装的 Windows 桌面软件**（.exe 安装包）。它的结构：

- **引擎（本体）**：切片 + 页码索引 + 检索 + 图谱 + skill 打包，藏在软件里面
- **脸1：客户端界面**——给**老板**用的，看得见摸得着，自己就能验收
- **脸2：MCP 接口**——给**AI** 用的，没有任何界面，智能体干活时自己来查书（本地服务，书库不变就一直在）

客户端 MVP 四个模块（老板已确认，全要）：

| 模块 | 干嘛的 |
|------|--------|
| ① 书架 | 拖书进去自动处理，每本书显示状态（处理中 / 可用），可删除 |
| ② 书内浏览 | 点开一本书：按章节翻、跳页码、看原文块 |
| ③ 试问题板 | 选一本书问一句，看它答什么、引用哪页——验证准不准 |
| ④ skill 开关面板 | 每本书的 skill 开 / 关一目了然，多本并行可管理 |

**不做（形态相关）**：不做移动端、不做多端同步、不做账号登录系统——单机自用，这些都砍。

## 三、明确做什么 / 不做什么（锁死，防反复改需求）

**做（三块能力）：**

| # | 能力 | 说明 |
|---|------|------|
| ① | 原文保真切片层 | 书切块、带页码、一字不改；去掉页眉页脚等垃圾，正文不丢 |
| ② | 检索 + 图谱串联 | 关键词 + 语义检索；概念之间能串联，都能回源到页码 |
| ③ | Skill 装配器 | **两层设计（老板定调：skill 内容不固定，按问题动态组装）**：① 单书入口 `query_book(书, 问题)`——按问题现场取原文、带引用回答；② 总入口 `query_library(问题)`——自动判断该翻哪本书（可多本），现场组装临时技能包，用完即弃。每本书也可独立打包成标准 MCP skill |

**不做（谁提都不做）：**

| 不做 | 原因 |
|------|------|
| 不训练模型 | 不需要，纯组装现成组件 |
| 不做给人看的图谱可视化 | 图谱是给 AI 查的，不是给人看的 |
| 不做"压缩/摘要版书" | 丢原文，违背"原汁原味" |
| 不自研底层 RAG/向量库 | 开源现成的好用，不重复造轮子 |
| 不追求技术先进 | 目标是"够用、好用、可溯源"的个人工具 |
| 扫描版 PDF（需 OCR） | 先不做，文字版优先 |

## 四、技术方案（v1.2 修正版——架构师联网核实后全部换血）

> 老板质疑"技术方案有雷"→ 派架构师联网逐个核实 → 4 项里 3 项有硬雷，全部替换。
> 修正原则：**全栈统一 Node 一门语言、纯本地不联网也能跑、中文书必须能搜、能打成单 exe。**

### 4.1 原方案踩的雷（为什么换）

| 原选型 | 雷（核实过的，不是猜的） | 换成 |
|--------|--------------------------|------|
| mcp-local-rag | ① 不支持 epub（只认 PDF/DOCX/TXT）；② 页码保真只有 PDF 有；③ 默认向量模型是英文向的，中文检索质量差；④ 它是黑盒服务不是零件库，控制不了切块流程 | 自研解析管线：pdfjs-dist（PDF）+ mammoth（DOCX）+ 自写 epub 解析，借鉴它的架构思路 |
| SQLite FTS5 默认分词 | FTS5 默认按空格切词，**连续中文整句被当成一个词，中文基本搜不到东西**（实测确认，不是理论风险） | FTS5 trigram 分词（SQLite 内置，中文任意片段可搜）+ better-sqlite3 开箱即用，Windows 免编译 |
| GraphRAG 实体抽取 | 抽实体/关系**必须调大模型**：本地跑 1MB 语料要 15~30 分钟还得 12GB 显卡，个人电脑基本跑不动，而且小模型抽出来的图谱全是噪声 | MVP 砍掉 LLM 抽取：图谱用零成本的确定性规则生成（目录层级 + 关键词共现 + 相似段落关联），够用且稳定；LLM 抽取留到 v2 当可选项 |
| fastmcp（Python 库） | 整个软件是 Node 体系，塞一个 Python 进去 = 安装包捆两套运行时，体积和复杂度双涨，零收益 | 官方 TypeScript SDK（@modelcontextprotocol/sdk），Electron 自带 Node，直接用，功能完全对等 |

### 4.2 修正后的技术栈表（锁定）

| 部件 | 用什么 | 干嘛的 |
|------|--------|--------|
| 桌面壳 | Electron 33+ | 软件本体，自带 Node 运行时 |
| PDF 解析 | pdfjs-dist 4.x | 按页提原文，页码天然保真 |
| DOCX 解析 | mammoth 1.x | 提纯文本 + 标题层级 |
| EPUB 解析 | 自研（解压 + XHTML 按章节解析） | 没有现成库能"保真+带结构"，自己写 |
| 存储 | better-sqlite3（内置 SQLite 3.50） | 一书一 .db，FTS5 + trigram 中文检索开箱即用 |
| 中文向量化 | @huggingface/transformers + bge-small-zh-v1.5 | 纯本地的中文向量模型（量化后约 50MB），首次下载走国内镜像，之后完全离线 |
| 向量检索 | 向量存 SQLite，Node 内直接算 | 单书几千~几万块，毫秒级，不用额外装库 |
| 图谱 | SQLite 两张表（节点/边），规则生成 | 目录树 + 关键词共现 + 相似段落，零模型成本 |
| skill 封装 | @modelcontextprotocol/sdk + zod | 两个工具：`query_book`（单书）+ `query_library`（总入口，自动挑书、动态组装临时技能包） |
| 打包 | electron-builder | 打成 Windows .exe 安装包 |

### 4.3 一个必须提前说清的诚实点

**epub 和 docx 这两种格式物理上没有"固定页码"**（页码是排版出来的，每台设备都不一样）。所以溯源规则定死为：

- **PDF**：溯源到**真实页码**
- **EPUB / DOCX**：溯源到**章节 + 段落位置**（同样能精确翻回原文，只是不叫"第几页"）

这不是偷工减料，是格式本身的物理限制。AI 回答时照样给出"出自哪本书、哪一章、哪一段"的可核对引用。

**诚实定位**：每个零件开源都有现成的，我们的价值在"组合"——保真原文 + 可溯源 + 一键 skill 化。技术不难，难在做扎实。

## 五、阶段计划（每步都有验收，过了才走下一步）

| 阶段 | 做什么 | 验收标准 | 预估 |
|------|--------|----------|------|
| **0 骨架验证** | 装 Electron + better-sqlite3 + pdfjs-dist；验证两件事：PDF 按页切出原文块、trigram 中文搜索真的能搜到 | 中文 2 字词和 4 字词都能搜中、返回正确页码 | 半天~1 天 |
| **1 切片保真层** | 三格式解析：PDF（页码）、DOCX / EPUB（章节+段落）；统一切片格式，原文一字不改 | 抽查原文能精确定位；三格式全跑通 | 1~2 天 |
| **2 检索 + 图谱** | trigram 全文 + 中文向量语义检索；规则生成图谱（目录树 + 关键词共现 + 相似段落） | 问一个概念，能带出关联切片并回源位置 | 1~2 天 |
| **3 Skill 装配器** | 先做单书 `query_book`（现场取材+引用），再加总入口 `query_library`（自动挑书、动态组装临时技能包，支持跨书） | 总入口问一个跨书问题，能自动牵出多本书的相关切片并各带出处引用 | 1~2 天 |
| **4 桌面客户端** | Electron 壳 + 四个模块：书架、书内浏览、试问题板、skill 开关 | 软件里拖一本书进去，四个模块全部能用 | 2~3 天 |
| **5 多本验证 + 打包** | 2~3 本不同类型书同时跑；打成 .exe 安装包 | 双击安装即用，定位准、引用对、AI 调书流畅 → 项目完成 | 1~2 天 |

> 顺序逻辑：先把引擎做扎实（0~3），再套客户端的壳（4），最后多书验证 + 出安装包（5）。每阶段结束给老板看结果。

## 六、风险与对策（提前说清，不留惊喜）

| 风险 | 对策 |
|------|------|
| 中文搜索搜不到（FTS5 默认分词的雷） | 已排掉：trigram 方案锁定，阶段0 第一件事就是实测验证 |
| 向量模型首次下载失败（约 50MB，国内网络） | 首跑走国内镜像站下载；失败可手动放文件 |
| better-sqlite3 是原生模块，Electron 打包偶尔要重编译 | 成熟组合，社区方案齐全；阶段0 就把"打包一个最小 exe"验证掉，不留到最后 |
| 免费 epub/PDF 下载源不稳定 | 多备几本候选（公版经典书，古登堡计划等），哪本能下用哪本 |
| skill 宿主兼容问题 | 走标准 MCP 协议（官方规范），任何支持 MCP 的智能体都能接 |
| 老板零代码 | 全程我干，你只做两件事：**提需求 + 验收**（每阶段结束给你看结果） |
