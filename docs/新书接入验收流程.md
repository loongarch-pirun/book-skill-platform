# 新书接入验收流程（冷接入五步 + 验收清单）

> 2026-10-13 建立。第 7 本书《孟子》实测走通，本文件即那次接收入库的复盘固化。
> 目标：**任何一本新书进来，零改码走完管线，且有机器验收兜底**——不是"看起来成功了"，
> 是每一项都有断言说了算。

## 零、原料准备

中文古籍（维基文库路线）：
```bash
node src/fetch-wikisource.mjs books/<书名>-zh-raw.txt "<文库页/篇一>" "<文库页/篇二>" ...
```
- 自带 UA + 429 长退避（15/30/60/90s），多页之间 sleep 2s。**429 是维基文库限流，不是代码错**，
  退避等它就过去，别反复重试把封禁坐实。
- 清洗规则已内置：header/footer/PD-old/Category 模板、`[[链接|显示]]`、`-{H|zh-hans:…;zh-hant:…}-`
  中文变体标记（**取繁体分支**，全书繁体路线）、`===N===` 小节转 `# 篇名·N` 标题行、
  页脚导航行「上一篇 回目录 下一篇」、wiki 分隔线 `----`。
- **接完必须目检**：`grep -c -- "-{\|{{\|\[\[\|^----"` 应为 0；翻头中尾三段看内容。

英文书：Gutenberg epub/pdf 直下，跳过这步。

## 一、转换 + 建库 + 灌向量（三步，零改码）

```bash
node src/txt2docx.js books/<书名>-zh-raw.txt books/<书名>.docx   # # 行 → Heading1 → 章节
node src/build-book.js books/<书名>.docx -o library/<书名>.docx.db
node src/embed-book.js library/<书名>.docx.db
```
- `# 标题` 约定是 2026-10-13 加的：txt 里 `# 篇名·N` 行 → docx Heading1 → build-book 识别为章节。
  不写 `#` 行，全书会挤进一个「前言」章（能用但目录废）。
- 建库保护：同源同内容跳过；**同源内容变（比如清洗规则升级后重抓）会被拒绝**——这是防作废编目的
  保护，不是 bug。确要重建：把旧 db（含 -wal/-shm）mv 走再建（沙箱垃圾桶不可用时 rm 会被
  safe-delete 拦，mv 是通行做法），或 `--force`。

### 1b. Markdown 直路线（V3 第二波起，开源技术书/一章一文件的语料）

```bash
node src/build-book.js <md目录|单文件.md> -o library/<书名>.md.db   # --title 可指定书名
node src/embed-book.js library/<书名>.md.db
```
- 目录书：一章一个 `.md`（凤凰架构/hello-algo/d2l/system-design-primer 式开源仓库）按自然序拼接；
  无标题篇用文件名补章。书名默认取上级目录名（`凤凰架构/fenix` → 凤凰架构），`--title` 覆盖。
- 解析器自动：`#` 标题 → 章节；代码围栏整段去（含 blockquote 里的围栏与 `#` 注释，防误判）；
  md 表格 → `a | b` 文本行；图片/链接地址剥掉留文字；HTML 组件残留（`<TitleInfos />`）丢弃。
- docx 路线同步升级（2026-10-15）：**表格内容不再丢**（w:tbl → 文本行）；无 Word 标题样式的文档
  用中文序号（一、/（一）/1.）+ 短行无标点启发式补章节（皮润作业式纯段落文档受益）。
- 语义分块（可选，`BSP_SEMANTIC=1 node src/build-book.js …`）：同章/同页相邻小块并到 ~400 字符
  （本类语料块长 p50≈100，不并则每问 6 段的上下文稀薄），超长块在相邻句余弦突变处补切；
  只动块边界不动字（拼回逐字保真），约 +20s/千块。存量书不加开关重建——属第三波渐进重建范围。
- 2026-10-16 五本 md 书实测（第二波-5，全过七关）：og-aws 579 块（1591→579）、SDP 1405（5927→1405）、
  hello-algo 691（3373→691）、凤凰架构 1227（3904→1227）、d2l 5506（33454→5506）。

## 二、结构验收（新写的闸门，七项）

```bash
node test/newbook-check.mjs library/<新库>.db        # SKIP_SEM=1 可跳过语义检查
```

| 检查 | 抓什么 |
|---|---|
| 账实相符 | meta.chunk_count / total_chars 与库里真数一致（**JS .length 同一把尺子**：SQLite LENGTH 数字符、JS 数 UTF-16 码元，非 BMP 罕字两种数法差 1——孟子里的 `𨪆` 实测踩过） |
| 章节结构 | docx/epub 必须分出章；PDF 按页切片无章节是既有设计（WARN 不 FAIL） |
| 块质量 | 空块、**纯符号垃圾块**（`----`/导航行，一条都不许有）、>3000 字病态块；1500~3000 是英文长句合法溢出 |
| 引擎一致 | meta.model == 当前引擎（assertEngine 卫兵） |
| 向量 | 全覆盖 + 维度 == 注册表 dim |
| FTS | 中间块一个 4 字短语 MATCH 能命中自己（trigram 字面腿活着） |
| 语义 | 中间块开头当问题编码，该块进全库余弦 top-5（embed→存→算链路活着） |

老书回归也跑一遍（`library/*.db`），防误伤。**已知 FAIL 遗留**（见任务 #58）：
P&P 4 块 >3000 字（达西 1.4 万字长信整块成块——库建于 2026-10-12 14:08，早于 17:29 的
epub 长段落切分改进，重建+重编目后才绿）。

## 三、金标准考卷（新书必须有题，否则"好不好"没门禁）

1. 在 `test/v2-eval.mjs` 的 GOLDEN 里加 `{ book: "<书名>.docx", q: "白话问题", g: ["书中原字"] }`。
2. **每条 g 先用 grep 回原文验真再写**（校勘差异是坑：孟子本版「天將降大任**是**人也」，
   別版作「斯人」；凭记忆写金标准 = 制造误判）。每题问法模仿既有题目：白话问、文言原文答。
3. 跑 `node test/v2-eval.mjs --rerank on`，看新书命中率；漏题如实分析（文言边界题容易漏，
   参见漏题档案）。
4. 更新 `test/eval-baseline.json`：**只有净提升才允许改**，漏题清单变化必须写进 commit message。

## 四、编目（LLM 层，智能体读任务书产 JSON）

```bash
node src/catalog-export.mjs library/<新库>.db          # → catalog-tasks/<同名>.json
# 读任务书（instructions 在文件里）→ 写 catalog-results/<同名>.json
node src/catalog-import.mjs catalog-results/<同名>.json --dry-run   # 先看校验
node src/catalog-import.mjs catalog-results/<同名>.json             # 正式入库
```
红线（都是踩过的）：
- **persons.match_names 每条都回原文 grep 验真**，导入程序会逐一验证，一条假写整批拒收。
- relations 的 a/b 必须出自 persons；关系陈述要有原文依据（不机器校验，靠人把关）。
- assignments 覆盖每个 cluster 恰好一次；themes 5~12 个且每个至少被用一次。
- 形式簇（問答體例、短答、轉告框架）老实给形式主题，别硬塞进话题主题。

## 四·四、云端清洗 + 行级净化（脏书必跑；位次：build → clean → inline → embed）

桌面「开始加工」管线自动按此位次跑（clean 有 key 才跑；inline 纯规则零 key 必跑）。
终端手动等价：

```bash
node src/clean-book.mjs library/<新库>.db                    # 整块判整块删（需 LLM key；GATE exit 2）
node src/inline-clean.mjs library/<新库>.db                  # 块内净化：L1 删行级噪音 + L2 跟帖切分
node src/inline-clean.mjs library/<新库>.db --dry-run        # 先看计划不落库（净化率/切块数/样例前后对比）
node src/inline-clean.mjs library/<新库>.db --restore --all  # 隔离账整体恢复（原文逐字回滚 + 删切出的新块）
node src/embed-book.js library/<新库>.db                     # 之后才灌向量（inline 改块集合会作废 emb）
```

行级净化治四类块内噪音（全部行级 trim 整行匹配，「楼主」开头行是正文不碰）：
页码行（块首/尾孤立数字）/ 楼层号（孤立「N楼」行）/ 跟帖署名（`作者：X回复日期`、`•用户+日期`）/
结构分隔线（`———`/`===`/`~~~`/`---`）。**L2 跟帖切分（2a 切不删）**：主帖段留原块、跟帖段切成
新块——问帖答帖分离后，检索不会再命中「通篇是读者提问」的块，cite 引文不裹署名页码。
护栏：I1 strip 后剩 <20 字拒收 / I2 跟帖段 <20 字丢弃、主帖段 <30 字不切 / I4 整书净化率
>40% 拒收（`--force-gate` 强过）、>25% 警告 / I6 版本闸。**落库自动作废 emb 与编目**
（块集合变了）——所以它必须在 embed 前，且跑完要重灌向量 + 重编目。

## 四·五、洗数据（V3 第二波起，可选；给每块产前置/标签/假设问题/摘要）

```bash
node src/enrich-book.mjs library/<新库>.db                 # 带 key 跑批（→ enrich-results/<同名>.json）
# 或无 key：--export 出任务书给外部智能体 → 产物放 enrich-results/<同名>.json
node src/enrich-import.mjs library/<新库>.db               # 入库（重跑四重验真后才写）
node src/enrich-import.mjs library/<新库>.db --audit       # 复查：回源率/覆盖率/三级摘要/原文指纹
```
红线：
- **入库前必看覆盖率**：缺号块（跑批失败的批）会留 NULL，`--audit` 的覆盖率不是 100% 就补跑再入。
- **content_hash 不符会整单拒收**（书重建过）——先重跑 enrich-book 再导入，别手动改产物里的 hash。
- 原文一字不改由两道保险盯着：静态断言 + 导入前后原文指纹比对（`--audit` 里的 textHash 可对外核对）。
- 私书派生数据（enrich-results/）默认 gitignore，不上开源仓库。

## 四·六、联动验收（V3R7-③ 起必跑：新书能不能被智能体「用起来」）

```bash
node books/_work/kb-e2e.mjs <新库名或db路径> --layer search,browse,cite
# 配了云端 AI 的机器上加 ,e2e 跑智能体端到端（会真实调用 LLM，烧 token）
```

四层各自验的东西：

| 层 | 验什么 |
|---|---|
| search | query_book 检索质量（题目文件可配：`books/_work/e2e-questions/<bookId>.json`，`[{q, expect:[...]}]`；缺省冒烟） |
| browse | 联动动线：`get_outline` 地图 → 最大章 `get_chapter`（8K token 闸行为）→ `read_range` 续读；无章书（PDF）自动降级 read_range |
| cite | `cite_check` 回验：从本书原文摘的真引文必须 exact 命中，编造引文必须被拒 |
| e2e | 真 LLM + MCP 工具 agent loop 完成工作备忘（工具调用次数/引文自检/无依据明说） |

新书入库即自动获得数据层能力（build-book 写 total_tokens/chapter_quality meta）——
本步验的是「智能体真的能用它完成工作」，不只是「书建好了」。

## 五、验收总账（全绿才算接入完成）

1. `node test/newbook-check.mjs library/*.db` 全 PASS（或只剩已知遗留项，记录在案）
2. `node test/v2-eval.mjs --rerank on` 新书题目命中 + `node test/eval-gate.mjs` 过门
3. `node books/_work/kb-e2e.mjs <新库> --layer search,browse,cite` 四层过（e2e 层有 LLM 配置时跑）
4. `npm test` 全套绿（fast 全量 + slow 全量）
5. `npm run mcp` 起服务，`list_catalog` 看得到新书主题/人物
6. git 提交 + 工作日志 + `npm run backup`
