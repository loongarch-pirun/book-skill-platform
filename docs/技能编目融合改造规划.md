# 技能×编目融合改造规划（skill × JSON × 图谱 × 向量 四线合一）

> 日期：2026-10-14 · 状态：规划稿（未动代码）
> 前置讨论：skill 是"地图不是背包"（防说谎）、query 是"猎犬不是地图"、骨架该从编目 JSON 自动生成——本规划把这三条结论落成工程。

---

## 一、目标一句话

把 skill 从"手写的孤岛"变成"长在结构化数据上的活地图"：**骨架从编目 JSON 自动生成（永不吹牛）**，图谱和向量通过 MCP 工具面暴露给外部智能体，四条线最后汇进同一句承诺——**引用必回原文**。

## 二、现状盘点：四资产各就各位

| 资产 | 现状（按代码实际） | 强项 | 缺口 |
|---|---|---|---|
| **编目 JSON**（nodes/edges/theme_vecs @SQLite） | catalog-export→智能体→catalog-import 三段闭环；`getCatalogSummary` 输出 themes/persons/relations | 结构权威（逐章验证）、跨重灌存活、match_names 逐字验过原文 | 只能经 `list_catalog` 整体浏览；**没进 skill 包**（skill 离开书库就变死数据） |
| **skill**（SKILL.md + chapters/） | 对话智能体手写蒸馏；save_skill 三道质检（结构/引用回源 60% 子句/coverage 声称校验） | 防幻觉铁闸、可分享 | **目录纯手写**——"81 章速查"谎报的根就是手写；coverage 靠事后查，不靠事前生成 |
| **图谱**（mention/relation/belongs 三种边，rule/llm 双层） | mention+主题点火喂检索当第三路信号；关系边主要价值在 list_catalog 浏览（扩散实测是噪声，默认关） | 关系题宝库 | 智能体只能"看一眼全图"，**不能按人物/主题深查**——关系网看得到摸不着 |
| **向量**（e5 384 维 + bge-reranker 复试官） | hybridSearch 主腿（语义+关键词双检索）；theme_vecs 主题点火 | 按意思找 | 智能体没有"以块找块"的相似查询出口 |

**核心矛盾**：四资产各自能干，但没有一条"从编目到 skill 到原文"的贯通动线——智能体要在 list_catalog（浏览）、query_book（检索）、save_skill（落盘）之间自己拼路，拼错就漂。

## 三、设计原则（硬规矩，与全项目一致）

1. **只做加法**：检索算法（hybridSearch/loadCatalogSignal）一行不动——图谱和向量继续当内部信号，本规划只给它们开"对外窗口"。
2. **新增不破坏**：旧 skill 包没有 catalog.json 照常工作；新工具独立注册，七工具行为逐字节不变。
3. **声称机器可验延伸到新资产**：catalog.json 和骨架目录从库里查出来直接生成（天然为真），不是让智能体"写完再查"。
4. **工具层无 LLM 铁律不变**：MCP 工具只做校验/查询/落盘，内容由对话智能体蒸馏。

## 四、融合架构（改造后）

```
编目 JSON（nodes/edges/theme_vecs @SQLite，权威结构）
   │                              │
   │ P-B 骨架自动生成              │ P-D 深查接口（get_person/get_theme）
   ▼                              ▼
skill 包（皮 + 骨同包）        外部智能体（任意 MCP 客户端）
   ├─ SKILL.md（人写导读，骨架自动）      动线：list_skills → read_skill(含catalog摘要)
   ├─ catalog.json（机器可读索引）  →    → list_catalog 看全图 → get_person/get_theme 深查
   └─ chapters/（引用块+锚点）           → query_book/query_library 取原文
   │                                    → similar_chunks 以块找块（P-E）
   ▼
原文 chunks（chapter/page 定位）← 全部路的终点：引用回源、跳转翻书
```

## 五、分批计划

### 第一批（P-A + P-B）：skill × JSON 融合【核心，一批做完，约 1 天】

**P-B 骨架自动生成器**（新文件 `src/lib/catalog-skill.mjs` + CLI `src/skill-scaffold.mjs`）

- 输入书 id，从库里查出真实结构，生成 skill 包"半成品"：
  - `catalog.json`：themes（含 note/块数/章节分布/chunk 锚点）/ persons（match_names/mention_count）/ relations——即 `getCatalogSummary` 的超集，多带 chunk id
  - `SKILL.md` 骨架：章节表**从 chunks.chapter 实际值生成**（永不吹牛），frontmatter 的 sources/coverage 自动填真值；正文留"导读/用法"空位给智能体填
  - `chapters/` 索引骨架：每章文件名 + 真实章题
- 智能体拿到骨架填空 → `save_skill` 走既有三道质检落盘（自动生成的 coverage 天然为真，coverage-check 从"抓谎报"变"走形式"）
- 用法：`node src/skill-scaffold.mjs <书名片段>` 打印 JSON（或写临时目录），对话智能体读后填空

**P-A catalog.json 进 skill 包**（改 `skill-store.mjs` + `register-tools.mjs`）

- `FILE_RE` 白名单加 `catalog.json`；save 时校验：可 JSON.parse、sources 与 SKILL.md frontmatter 对齐（先 warning 后收紧）
- `read_skill` 返回带 `catalog` 摘要（包内有就读，没有返回 null——旧包零影响）
- `list_skills` 加 `has_catalog` 字段

**验收**：catalog-test 加骨架生成断言（章节表=库里实际章节、coverage 自动值=引文实际覆盖）；skill-store-test 加 catalog.json 校验断言；旧包兼容断言。

### 第二批（P-D）：图谱查询接口【MCP +2 工具，7→9，约半天】

**`get_person(book, name)`**：人物深查——match_names、mention_count、关系边（a/b/note）、mention 代表块预览（top5，带 chapter/page + 80 字预览）
**`get_theme(book, name)`**：主题深查——note、覆盖块数、章节分布、代表块预览

- 落点：`catalog.mjs` 加 `getPersonDetail/getThemeDetail` 两个只读查询（与 getCatalogSummary 同层）；`register-tools.mjs` 注册
- **图谱继续当检索信号不动**——这两个工具是"把浏览升级成查询"，让关系网从"看得到"变"按图索骥能摸到原文块"
- description 写清动线：`list_catalog 看全图 → get_person/get_theme 深查 → query_book 取原文`
- 验收：catalog-test 加两查询断言；register-tools 冒烟 + guard-test 静态断言（工具必须注册、检索层零改动守卫）

### 第三批（P-E）：向量相似查询【MCP +1 工具，9→10，约半天】

**`similar_chunks(book, chunk_id | text, topN)`**：给一块原文或一个块号，向量余弦找最相似 N 块（emb 都在库里，纯排序，零新模型）

- 用途："这段话还有哪里讲过类似的事"——跨章节聚合主题的刚需
- 落点：新导出 `similarChunks`（放 search.mjs 同层新文件 `similar.mjs`，不碰 hybridSearch）；register-tools 注册
- 验收：单测（自相似排除/topN 夹取）+ 冒烟

### 评估项（记录在案，数据说话后才做）

- **P-C 引用块号锚点**（`〔别名·章节#chunk123〕`）：精度收益 vs 校验变脆（引文跨块就挂），先在骨架 catalog.json 里带 chunk id 观察需求，不急着改 CITATION_RE
- **P-F skill 命中加分**（第四路检索信号）：走 BSP_EXPAND 同款流程——实验矩阵 + eval-gate ≥88 且漏题不新增才许开，默认关

## 六、明确不做（防跑偏）

- 检索算法/权重/引擎任何改动（BSP_* 全家不动）
- 编目重跑、图谱重建、模型更换
- MCP 工具内接 LLM（工具层无 LLM 铁律）
- 一次换掉手写 skill——骨架生成是**可选加速**，旧包/手写包继续合法

## 七、风险与回滚

| 风险 | 对策 |
|---|---|
| catalog.json 校验过严挡落盘 | 分两步：先 warning 观察一周，再升 error |
| 新工具 description 误导智能体动线 | 描述里写死推荐动线；MCP 冒烟逐工具过 |
| 骨架生成的章节表撞上无章节书 | 小书/无章节书走 chapter-fallback 同款兜底（编目聚类已有先例） |
| 每批独立 commit | 任一批可单独 revert，互不牵连 |

## 八、总验收清单

- [ ] MCP 冒烟：七→十工具全通，旧客户端零感知
