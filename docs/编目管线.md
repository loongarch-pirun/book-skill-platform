# 编目管线 —— 云端大模型 × E5 协作把书"编目"成可检索的图谱

> 成文于 2026-10-12 加固轮收尾。管线现状：**6 本书全编目完成**
> （主题 42 / 人物 55 / 关系 47，belongs 边 2520 + mention 边 3400），金标准 86 分。

## 一、它在整个平台里的位置

```
书文件(pdf/epub/docx)
   │  build-book.js        切片保真层（原文一字不改，块带页码/章节）
   ▼
library/<书>.db  ──────  chunks 表 + FTS5 trigram
   │  embed-book.js       向量化 + 规则图谱（rule 层）
   ▼
   ├── catalog-export.mjs ① E5 聚堆 → ② 生成任务书 JSON
   │        │
   │        ▼
   │   智能体（云端大模型）读任务书 → 产出编目结果 JSON
   │        │  （只传词频统计+代表块样本，不传全文：省 token、护隐私）
   │        ▼
   └── catalog-import.mjs  ③ 五重校验 → ④ 入库（llm 层 + theme_vecs）
            │
            ▼
       search.mjs 检索时第三路信号（人物 mention + 主题语义 + 并列裁决）
```

关键设计：**图谱双层**。`nodes/edges` 都有 `source` 列——`rule`（规则层，embed-book
每次重灌重建）与 `llm`（编目层，一次入库长期存活）。**换引擎重灌向量只清 rule 层，
编目成果安然无恙。**

## 二、五重校验（import 时全过才入库）

1. **JSON 语法**（容 markdown 代码围栏）
2. **zod schema**（task_ref/themes/persons/relations/assignments 结构）
3. **人物验真（防幻觉红线）**：每个 match_name 逐一 `instr` 检查原文真实存在，
   一条不存在 → **整批拒绝**。历史教训：`Anne` 是 `manners` 的子串（146 块误中）、
   `孔子` 二字在学而篇原文不存在（只有 子曰/夫子）——写法必须逐字验真
4. **cluster 全覆盖**：任务书里每个 cluster id 恰好被 assignment 覆盖一次
5. **引用完整性**：relations 的 a/b 必须是已声明人物；theme 必须被使用

## 三、数据布局

| 表 | 内容 | source 列 |
|---|---|---|
| `nodes(type,name,ref)` | theme / person / 概念节点 | rule \| llm |
| `edges(src_type,src,dst_type,dst,kind,weight,ref)` | belongs(块→主题) / mention(块→人物) / relation(人物↔人物) / 相似边/结构边(规则) | rule \| llm |
| `theme_vecs(name, vec)` | 主题名向量（主题语义点火用，384 维 e5） | — |
| `meta` 追加键 | `catalog_model` / `catalog_at` / `catalog_themes` / `catalog_persons` / `catalog_chunk_count` / `catalog_text_bytes` | — |

`catalog_chunk_count` + `catalog_text_bytes` 是**保真基线**：编目测试用它们断言
编目入库没动过原文一个字节。

## 四、检索端信号（search.mjs 第三路）

- **人物路**：问题里的名字（词边界匹配 match_names）→ mention 边取块，
  IDF 衰减（`min(1, 30/mention_count)`——高频人物弱信号），同块信号求和封顶 1
- **主题路**：`cos(qv, theme_vecs)` 相对 margin 命中 → belongs 边取块
- **并列裁决**：复试官分数加 `BSP_CATALOG_TIE × 信号强度`，只裁决近并列
- 信号地板 0.15：太弱的信号直接无效化（**帮不上忙的信号不许扰动**）

## 五、常用操作

```bash
# ① 出任务书（全部书）
node src/catalog-export.mjs --all
# ② 智能体编目（人来做：读 catalog-tasks/<书>.json，产 catalog-results/<书>.json）
# ③ 校验+入库
node src/catalog-import.mjs catalog-results/<书>.json --dry-run   # 先看校验
node src/catalog-import.mjs catalog-results/<书>.json             # 入库
node src/catalog-import.mjs --all                                  # 全部

# 回滚整本书的编目（rule 层与原文不动）
node src/catalog-import.mjs --rollback library/<书.db>
```

**换引擎时**：`BSP_EMBED_MODEL=xxx node src/embed-book.js library/<书>.db xxx`
→ 向量重灌（rule 层重建），**但 theme_vecs 还是旧引擎的** → 编目层的主题语义路
会自动跳过（引擎不一致保护），必须**重新编目一遍**（重新 export → 编目 → import）
才能恢复主题路。importCatalog 入库前有引擎卫兵：库与当前引擎不同空间直接拒绝。

## 六、环境变量速查

| 变量 | 默认 | 作用 |
|---|---|---|
| `BSP_EMBED_MODEL` | e5 | 查询/建库向量引擎（唯一入口 lib/models.mjs） |
| `BSP_RERANK` | 开 | `=0` 关复试官（诊断用） |
| `BSP_CATALOG` | 开 | `=0` 关编目信号（对照组/回滚） |
| `BSP_CATALOG_W` | 0.3 | 编目信号权重 |
| `BSP_CATALOG_TIE` | 0.02 | 复试并列裁决强度 |
| `BSP_THEME_MARGIN` | **0.05** | 主题点火边距。**红线：不许低于 0.05**（主题名余弦挤成一团，0.025 曾把目盲题打翻，0.03 实测打翻 pemberley） |
| `BSP_EXPAND` | 关 | `=1` 开人物关系一跳扩散（默认关：扰动 > 收益） |
| `BSP_FTS_KW` | 开 | `=0` 字面腿退回旧整句短语行为 |
| `BSP_FTS_W` | 0.5 | 字面腿权重（上限 0.5） |
| `BSP_VEC_CACHE_MB` | **0（关）** | 向量矩阵缓存。大书库（几十本）查询变慢时开 200；6 本书规模实测无收益 |
| `BSP_ROUTE_PRESCREEN` | 6 | 路由质心预筛门槛：书多于它才粗筛 |
