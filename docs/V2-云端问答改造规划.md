# V2 云端问答改造规划（加法版）

> 一句话目标：给客户端加上「对话式问答」——本地检索找依据（一行不改），云端模型写回答（全新），回答带引用可跳原文（复用现成）。
> **核心原则：只做加法。** 不删行、不改行；必须碰老文件时只"加行"，每处改动 `git diff` 一眼可验。
> 底线：**检索和原始书库永远留在本地，云端只碰「回答」这一层**；不填 key = 一切照旧。
> 状态：规划定稿（2026-10-13 夜）。执行记录见文末第 8 节。

---

## 0. 背景：为什么做、做什么、不做什么

**现状（v1）**：

- "问一问"返回 4 段最相关的原文 + 引用徽标（点了跳原文）——**没有人"写答案"**，生成这步一直外包给外部 AI（MCP / 提示词模式）。
- 需求：内置"会说话"的智能体——填一个 API key，基于书库直接问答。

**三层模型**（想清楚"智能体改造"的边界）：

| 层 | 是什么 | 现状 | 本规划 |
|---|---|---|---|
| ① 检索层 | 切片 / 向量 / 编目，负责"找得到、找得准" | ✅ 已有（52 题考卷 + 防幻觉回源护着） | **不碰** |
| ② 生成层 | 云端模型把检索片段写成回答 | ❌ 无（生成在外包） | ✅ **要做**（= 本规划） |
| ③ 决策层 | AI 自主决定"怎么查、查几次、用什么工具" | ✅ MCP 已覆盖（外部智能体接入） | **不做**（不重复造） |

结论一句话：**智能体是壳，可信是芯。** 做 ②（固定管道：先本地检索、后云端生成），不做 ③（自主决策——那是 MCP 给专业用户的路；客户端里重造一遍，既费 token 又不可控）。

**明确不做（边界）**：

- 多供应商专有协议 —— 只做 **OpenAI 兼容**一种，一套代码通吃
- 流式输出 —— V2 先非流式（loading 文案），后续再说
- 对话落盘持久化 —— 放 P4（引用快照一起）
- MCP / CLI 侧改动 —— 另一条入口，V3 再说
- 本地生成模型 —— "本地"= 保持现状（检索+引用），不新增下载

## 1. 八条硬规矩（"只做加法"的落实）

1. **能新建文件就新建**；必须碰老文件时**只"加行"，不删行不改行**
2. **不填 key = 零变化**：没配置时新功能显示引导卡片，现有四个页面一字不动
3. **检索层零改动**：直接复用现有 `ask()`（与"问一问"同一条代码路径）；52 题考卷 / 编目 / 防幻觉回源全不碰
4. **校验才显示**：云端答案必须过引用校验（引用编号存在 + 引文命中片段原文），不过的引用剔除；全不过则降级
5. **失败自动降级**：key 错 / 欠费 / 断网 / 超时 → 回退"展示原文片段" + 人话提示
6. **零新依赖**：Node 内置 `fetch` 调 API，不引任何 SDK
7. **key 加密存**：safeStorage 加密（明文不落盘）；发出去的只有"问题 + 检索片段 +（可选）技能包章节"
8. **每步独立提交**：任何一步出问题，`git revert` 那一个提交即回到原状

## 4. 实现要点（技术设计）

### 4.1 协议与配置

- 只做 **OpenAI 兼容**：`POST {baseUrl}/chat/completions`，`Authorization: Bearer <key>`。
- 配置三个字段：`baseUrl` / `apiKey` / `model`；placeholder 给 DeepSeek、GLM 示例（不硬编码某一家）。
- `temperature` 默认 0.3（答案求稳）；`max_tokens` 默认 1500；超时 60s（`AbortController`）。

### 4.2 key 存储（`llm-config.mjs`）

- 存 `userData/llm.json`：`{ baseUrl, model, apiKeyEnc: "<base64>" }`。
- **加密在注入层完成**：main.js 传入 `safeStorage.encryptString / decryptString / isEncryptionAvailable`；模块本身零 Electron 依赖（测试注入假加密器）。
- 加密不可用（罕见）→ 明文存 + UI 警告；**key 永不进日志、永不回显**（UI 只显示尾 4 位）。

### 4.3 提示词与回答格式（`buildMessages` / `parseAnswer`）

- system：角色（"根据给定的原文片段回答问题"）+ 铁律（只能依据片段；引用必须逐字抄；找不到就说"书中没有相关内容"；不得编造）+ 输出格式。
- **输出格式（JSON）**：

  ```json
  { "answer": "回答正文（文内可用 [1] [2] 标注引用）",
    "citations": [ { "n": 1, "quote": "逐字抄自片段1的一整句" } ] }
  ```

- user message：问题 + 编号片段（`[1] 《书名》·位置：原文…`）+（可选）技能包章节。
- 解析：容忍 ```json 围栏（复用 `parseResultText` 同款宽容策略）；解析失败 → 降级。

### 4.4 引用校验（`verifyAnswer`，防幻觉延伸到生成层）

- 结构校验：`answer` 非空；`citations[].n` ∈ 有效片段编号；`quote` 非空。
- **引文回源**：`quote` 归一化（去空白/统一标点）后必须"命中"对应片段——继承 `skill-store` 引用回源验证的思路（子句命中率 ≥ 60%），独立实现。
- 逐条过滤：不过的引用剔除，UI 注明"有 N 条未通过核验已隐藏"；**全部不过 → 整条降级**（只给原文片段）。
- 展示给用户的每一条引用徽标 = 校验过的（可信是芯）。

### 4.5 降级矩阵

| 情况 | 行为 |
|---|---|
| 未配置 key | 引导卡（去填配置），检索照常 |
| 401/403 | "API key 无效或无权限" + 引导改配置 |
| 404 | "接口地址或模型名不对" |
| 429 | "请求太频繁或余额不足" |
| 5xx / 网络错 / 超时 | "连不上模型服务（检查网络或接口地址）" |
| 回答解析失败 / 引用全不过 | "云端回答未通过核验" → 展示原文片段（现有体验） |

> 所有错误都走"人话化"（沿用引擎层既有习惯），UI 永不裸露英文堆栈。

### 4.6 会话与历史

- **渲染层持有 history**（最近 6 条 / 3 轮），主进程无状态——最简单，不用做持久化。
- 每次 send：`messages = [system, ...history, user(问题+新检索片段)]`——**每轮检索都是新鲜的**（不把旧片段带进新问题）。

### 4.7 复用清单（一行不改的部分）

- 检索：`engine.ask()`（含 H3 关书过滤、技能包 attachSkill）
- 跳转：`views-reader.js` 的 `jumpTo`（已导出）
- 引用事件：`cite`（已绑全局 `#main`）
- 解析宽容：`catalog.mjs` 的 `parseResultText` 同款策略
- 人话化：`engine.humanizeError` 同款风格
