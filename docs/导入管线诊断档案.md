## 二、议题 B｜拖书没反应（本轮主诊断）

### 现象
双击 exe（或 npm start）后，把桌面上的 txt 拖进窗口 —— **毫无反应**，连提示都没有。

### 诊断结论：四个缺陷叠加
| 编号 | 级别 | 问题 | 位置 |
|---|---|---|---|
| **G-01** | P0 | spawn 缺 `ELECTRON_RUN_AS_NODE=1`：打包态 `process.execPath` 是 exe，子进程被当 GUI 启动，脚本不跑且**永不退出** → 卡死在「向量化中」/「准备文件」 | `jobs.mjs` 两处 spawn |
| **G-02** | P0 | `File.path` 在 Electron 32+ 已移除（当前 ^44.7.0），恒 `undefined` → 被解析成当前目录 → 报出与真因不符的「不支持的格式 .?」 | `views.js` drop 处理 |
| **G-03** | P1 | 拖拽热区只认 `#dropzone` 方框（仅书架页），拖到别处**静默 return**；`preventDefault` 写在热区判定之后 → 落空文件会触发浏览器导航 | `views.js` 拖拽监听 |
| **G-04** | P1 | `jobs:scanPending` 已注册但 preload 未暴露；且主进程 scanPending 在 `createWindow()` 之前执行，事件经 `win` 转发时被守卫静默丢弃 | `preload.js`、`main.js` |

### 「为什么我拖了没反应」的完整解释
1. 你大概率**拖在了非方框区域**（或不在书架页）→ 旧代码第一句 `if (!dz) return;` 直接静默返回（G-03）
2. 就算拖准了 → 取路径用的 `f.path` 恒为 undefined，导入注定失败（G-02）
3. 就算路径对了（开发态曾经能跑）→ 打包版 exe 会在「向量化」子进程处永久卡死（G-01）
4. 重启后「待编目」状态也恢复不了（G-04）

**而「模型已就绪」与导入无关**——那是问答引擎那条线，导入走的是 jobs 管线。

### 补充澄清：编目第 ④ 步不是缺陷
任务书（`catalog-tasks/xxx.json`）自动生成后，**答案 JSON 必须由大模型/智能体产出**再放回
`catalog-results/`，然后点「导入编目结果」→ 五重校验入库。
这是「编目质量可控」的设计核心，不是自动化缺口。本轮新增「一键生成提示词」把这步
从「人工整理任务书」变成「复制粘贴」（零 API 依赖、不花钱）。

## 三、议题 C｜链路能力边界（代码实测矩阵）

| 步骤 | 能力 | 开发态 `npm start` | 打包态 exe（修前） |
|---|---|---|---|
| ① 切片 | pdf / epub / docx 原生；txt 先转 docx | ✅ | ✅（进程内，无 spawn） |
| ② 向量化 | spawn `embed-book.js`：向量 + 概念图谱，零 LLM | ✅ | ❌ 卡死（G-01） |
| ③ 生成编目任务书 | 聚堆 + 任务书落盘，零 LLM | ✅ | 到不了这步 |
| ④ 产出编目结果 | **需外部大模型按任务书产出 JSON**（设计如此） | ⚠️ 人工/智能体 | 同左 |
| ⑤ 导入入库 | 五重校验 + 主题/人物/关系入库 | ✅ | 同左 |

**修 G-01 的本质差异（两次实测确认）**：
- 开发版 `electron.exe` 收到 `.js` 参数 → 把它当 app 入口执行、跑完退出 → 所以 `npm start` 拖书能走通
- 打包版 exe 收到同样参数 → 忽略它、启动自己的界面 → 永不退出 → 卡片永久卡死

## 四、附：排查方法（如何区分 UI 入口问题和主进程链路问题）

1. **看有没有「动静」**：拖拽后有无 toast / 书架横幅变化。完全无动静 → 先查渲染层入口（热区、取路径）；
   有横幅但卡在某步 → 查主进程管线（jobs.mjs）。
2. **控制台**：`Ctrl+Shift+I` 开 DevTools，看 Console 红色报错；渲染层错误全在这里。
3. **终端输出**：`npm start` 的终端窗口会打印主进程日志与子进程输出（打包态无终端，改看卡片 error 文案）。
4. **静态确认拖拽链路**：drop 事件 → `study.filePathOf(file)`（preload 的 webUtils）→ `importFile` →
   IPC `books:import` → `jobs.startImport`。
5. **静态确认子进程链路**：`jobs.mjs` `runEmbed` / `txtToDocx` 两处 spawn → `EMBED_SCRIPT` / `TXT2DOCX_SCRIPT`
   （路径按 `import.meta.dirname` 拼，asar 内可执行），env 必须带 `ELECTRON_RUN_AS_NODE=1`。
6. **打包态探针**（本机验证 exe 能否跑脚本）：
   ```bash
   ELECTRON_RUN_AS_NODE=1 release/win-unpacked/BookSkillPlatform.exe resources/app.asar/src/embed-book.js
   # 应打印用法并退出；不带变量跑同一命令则无任何输出（GUI 模式吞掉参数）
   ```
