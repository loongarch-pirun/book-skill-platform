## 0. 先校准：本项目的"暴力面"到底在哪

这个平台**不是聊天机器人**。引擎层是证据检索器——只负责"从原文找出最相关的块并附引用"，最终措辞由对话智能体完成。所以"AI 幻觉"必须拆成两半治：

| 幻觉面 | 责任人 | 机器能管吗 | 现有缰绳 | 本次动作 |
|---|---|---|---|---|
| 编目产出（假人物/假关系/假主题归属） | 编目智能体 | 能 | catalog-import 五重校验（match_names 逐一 instr 验原文） | 攻击它 |
| 技能包内容（假引文/假覆盖声称） | 技能智能体 | 能 | citation-check 引文回源 + coverage-check 覆盖核对 | 攻击它 |
| 考卷金标准（答案本身是幻觉） | 人 | 能（反验） | 目前靠人工 grep，**无自动断言** | 补反验测试 |
| 检索判决（把 A 的话判给 B、无答案硬答） | 引擎 | 部分 | 无探针 | 补探针测试 |
| 最终回答措辞 | 对话智能体 | 不能全管 | 引用徽标可溯源 + 出厂清点单 | 登记为残余风险 |

**核心思路：暴力测试不是从零写测试，是拿 adversarial 弹药攻击现有闸门，再补没有闸门的地方。**

沙箱边界声明（诚实前置）：Electron 渲染进程在本沙箱起不来（连 about:blank 都崩），GUI 类测试只能真机执行；其余全部可自动化。

## 1. 攻击面地图（六大类 → 本项目弹药）

| 测试大类 | 具体攻击向量 | 现有防线 | 缺口（本次补） |
|---|---|---|---|
| 文件解析 | 截断 zip、zip 炸弹、空 document.xml、垃圾 XML；空/纯符号/纯数字 txt、无章节、满行 `#` 标题、10 万字符无标点单段、UTF-16/BOM、代理对密集、SQL 注入串当章节名 | build-book 内容变更保护、txt2docx 标题约定 | 无系统 fuzz → parser-fuzz |
| 信息提取 | 章节跳号/重号/空标题、ID 错位、块数账实不符 | newbook-check 账实关 | 对验收脚本自身投毒（"看起来合格的坏书"） |

## 2. 分组执行计划

### P0 幻觉爆破（最高优先——闸门是幻觉的最后防线，门漏了比功能 bug 致命）
**目标**：证明四道门"该拒的拒得掉、该放的放得对"。
**弹药**：
- 编目门：假 match_names（复刻 Anne/manners 子串陷阱、把真人名安错人）、块 ID 越界/负数/非数字、task_ref 不匹配、重复主题名、关系指向不存在节点、belongs 引用不存在块、主题覆盖块数为 0
- 技能门：引文边缘造假（换标点、删字到 60% 命中率边缘、弯引号变体）、覆盖声称造假（"八十一章"中文数字——**先补解析再炸**）、索引表指向不存在文件、frontmatter 声称与正文不符、slug 路径穿越（`../`、绝对路径）、超限文件（单文件 >512KB / 整包 >1MB）
- 考卷门：把 v2-eval GOLDEN 全部金标准词**自动 grep 回对应书原文，写进测试常驻**——未来加题带幻觉直接红
- 检索门：无答案探针（"孟子怎么看股市"）断言低分不硬答；篡改主语探针（"孔子曰：民为贵"）断言不把孟子的话判给孔子
**产出**：`test/hallucination-fuzz.mjs`（新增，挂 test:fast）；skill-store 中文数字声称解析修复。

### P1 文件解析 fuzz
**目标**：坏输入必须有确定性行为——要么人话干净拒绝，要么干净成功且内容守恒；**禁止静默丢内容、崩溃裸栈、无限循环**。
**弹药**：见攻击面地图。每个畸形文件断言三选一：UserError（带人话）/ 成功且字符账对平 / 超时兜底（30s 硬顶）。
**产出**：`test/parser-fuzz.mjs` + `test/fixtures/badfiles/`（构造的畸形文件入库，可复用）。

### P2 任务流程闭环爆破
**目标**：任何一步死掉，重启后系统状态确定可知。
**弹药**：kill -9 于切片/向量/编目等待三个中点 × 重启 scanPending 行为矩阵；并发双 import 同书（炸已知并发锁缺口）；结果晚到（停住 → 放合法结果 → resume 入库）；结果截断/非法 JSON/坏 ref；外部改动库后 import（引擎卫兵）；txt→docx 转换中途死。
**产出**：扩充 `test/jobs-test.mjs`（挂 test:slow）。

### P3 稳定性长流程
**目标**：长时间多阶段不劣化。
**弹药**：连续导 3 本书不重启进程（RSS 前后差 <100MB 粗线）；同书反复进出翻书 50 次（防重入）；perf-test 复跑对账（延迟劣化 >20% 报警）；eval-gate 全套（88 基线红线）。
**产出**：`test/soak-test.mjs`（新增，挂 test:slow，可手动触发）。

### P4 桌面真机勾选单（只能你做）
**目标**：GUI 边界人肉过一遍。勾选单：拖 100MB 真 PDF、取消进行中导入、切书瞬间取消、skill-state.json 手改成非法 JSON、断网问一问、导航连点 20 次、最小化/恢复、装正式包双击。
**产出**：`docs/真机验收勾选单.md` + 你回报的问题我逐条定位修。

### P5 供应链与打包收尾
**目标**：上线级卫生。
**弹药**：npm audit 10 moderate 逐条定去留（能升升、不能升写豁免理由）；build-book unhandledRejection 丢堆栈修复；打包三层验收复跑（asar 对账 / 过滤后树真跑 / STONE3）。
**产出**：修复 + `docs/依赖审计记录.md`。

## 4. 执行原则（红线不变）

1. 发现先入账再分级；**宁可误报，不可漏报**；修不完的登记，不删。
2. 每条问题定位到 文件:行；每条修复配对应断言常驻（防回归）。
3. **不删考题、不改判分、不为提分调检索算法**（项目哲学：如实记录）。eval-gate 两道硬门不变：≥88 且漏题 ⊆ 基线漏题。
4. "零幻觉"的诚实定义：**机器可判的幻觉清零**（四道门该拒全拒）；模型级残余风险（e5 文言边界等）登记在案，不假装不存在。
5. 每批修复 = 一批发现 + 12 套绿 + 一个 commit；不攒大合并。
