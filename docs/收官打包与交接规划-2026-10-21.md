## 一、现状清单（摸底结论）

### 1.1 打包链路现状

| 项 | 现状 |
|---|---|
| 打包命令 | `npm run dist`（electron-builder 26，nsis，oneClick，per-user 安装到 `%LOCALAPPDATA%\Programs\BookSkillPlatform`） |
| 进包内容 | `files` 只含 `src/**/*` + package.json + 生产 node_modules。**没有 library/skills/books/模型** |
| 上个安装包 | `release/BookSkillPlatform Setup 0.1.0.exe` = 156MB，**纯代码**。装上去书架是空的，首次提问时从 hf-mirror 下载约 700MB 模型 |
| 打包态数据解析 | `src/desktop/paths.mjs` 三层：env > userData/config.json > 默认（未打包=项目根，打包=userData）。首启向导让用户「选现有书库文件夹」或「从空白开始」 |

**结论：现在的安装包离「打开就能用」差三样——书库、技能、模型都没进包。**

### 1.3 模型现状（老板说「两个小的 + 一个 700 兆」的映射）

| 模型 | 大小 | 用途 | 处置 |
|---|---|---|---|
| `Xenova/multilingual-e5-small`（int8） | 129M | **默认向量引擎**（建库+查询都靠它） | **进包**（小的之一） |
| `Xenova/bge-small-zh-v1.5` | 23M | 注册表备用引擎（BSP_EMBED_MODEL 可切） | **进包**（小的之二，便宜） |

**进包合计 ≈ 740M**（129+23+588）。`.models` 剩下 2.7G 留在本机开发目录，不影响安装包。

### 1.4 配置卫生（打包前要处理的）

1. `library/skill-state.json` 当前**关着 4 个技能**（opinion-archaeology / citation-check / engineering-research / humanities-reading）——这是 10-21 测试开关的残留，进包前要复位成全开。
2. `library/usage-policy.json` 闸机默认「工作日 9:00-18:30 开放、周末关」——交接后智能体周末连会被拒，文档要写明，或进包策略改为全天开（待拍板 #3）。
3. `%APPDATA%/BookSkillPlatform/` 本机不存在——老板没在真机跑过安装包，首启路径是处女状态，正好用来验种子化。

### 1.5 MCP 入口现状与实测

- 入口：`src/mcp-server.mjs`（stdio，18 工具）。CLI：`node src/mcp-server.mjs`，env 三件套 `BSP_LIB_DIR / BSP_SKILLS_DIR / BSP_MODELS_DIR`。
- **项目态已实测通**：node 直跑 + initialize/tools/list/list_books 全过（真库 18 本）。
- **安装态已实测通（零成本方案）**：安装包里 src 在 app.asar 里，普通 node 读不到；但用安装包自带的 Electron 以 node 模式跑即可——

```
ELECTRON_RUN_AS_NODE=1 BookSkillPlatform.exe <安装目录>\resources\app.asar\src\mcp-server.mjs
```

实测（2026-10-21 22:40，win-unpacked 里真跑）：initialize / tools/list / **tools/call list_books 全部正常返回**，better-sqlite3 原生模块在 Electron 的 node 下加载无误，18 本书数据完整。**不需要 asar 解包、不需要用户装 Node、不增加包体。**

## 二、安装包内容方案

### 2.1 extraResources 四件（package.json build 段新增）

```json
"extraResources": [
  { "from": "library", "to": "library", "filter": ["**/*"] },
  { "from": "skills",  "to": "skills",  "filter": ["**/*"] },
  { "from": "books",   "to": "books",   "filter": ["**/*", "!_work/**"] },
  { "from": ".models", "to": "models",  "filter": [
      "Xenova/multilingual-e5-small/**",
      "Xenova/bge-small-zh-v1.5/**",
      "onnx-community/bge-reranker-v2-m3-ONNX/**",
      "!onnx-community/bge-reranker-v2-m3-ONNX/onnx/model_q4.onnx"
  ] }
]
```

落到 `<安装目录>\resources\` 下：library(93M) / skills(80K) / books(3.4M) / models(740M)。

### 2.2 首启种子化（新增逻辑，改 3 个文件）

- **触发时机（对齐审查修正，见第八节偏差 1）**：不在 engine.init 里同步拷贝（拖慢开窗且无反馈），改为**向导按钮触发式**——用户点「使用内置书库」→ 主进程拷贝 → configSet → location.reload()，与现有「选现有库」按钮同构，零新机制。拷贝期间按钮变「正在准备书库…」禁用态 + toast，不开新 IPC 通道。
- **paths.mjs / engine.mjs**：拷贝 `resources/library|skills|books` → userData 同名目录（约 100M，秒级）；modelsDir 解析改为「**内置资源优先**」——打包态下 userData/.models 不存在且 resources/models 存在时，直接用 resources/models（只读推理，不拷 740M、不重复占磁盘）。用户已有的 userData/.models 永远优先（可能装着下载的新模型）。
- **幂等与优先权**：userData 里已有 .db 就不覆盖（用户数据永远赢）；config.json 写入三个目录解析结果，向导不再出现。
- **失败降级**：拷贝失败（磁盘满/权限）不卡死启动，落回现在的向导三选一。
- **向导改版**（app.js）：三个选项——①「使用内置书库（推荐，18 本书 + 7 个技能 + 模型已就绪）」②「选择现有书库文件夹」（老项目迁库）③「从空白开始」。模型文案从「首次提问下载约 700MB」改为「已内置，即开即用」。
- 未打包态（npm start / npm test）**零影响**：种子化只在 `packaged && firstRun` 时触发。

### 2.3 包体估算

156M（现有代码） + 93M + 3.4M + 0.08M + 740M ≈ **992M 原样 → nsis 压缩后约 0.9~1.0GB**。onnx/db 已是压缩格式，压不动太多；这个体积 U 盘/网盘/内网分发都可接受。

1. **打包前配置卫生**：skill-state 复位；usage-policy 按拍板改；library wal 已干净（全 0 字节）无需 checkpoint

5. **门禁**：`npm run test:fast` + `npm run lint` + `npm run skill:validate`（7 包 0 error 0 warning）+ `node src/check-skills.mjs`（7 包全绿）+ eval-gate（≥93 基线）

## 七、风险与回滚

- **种子化误拷**：只在 `packaged && firstRun` 触发；userData 已有数据绝不覆盖；失败落回向导。最坏情况=用户自己选目录，与现状无异。
- **模型只读失败**：若 transformers 需要写缓存（缺文件触发下载），resources 在 per-user 目录下可写，降级为自动下载，不崩。
- **包体超预期**：若压缩后 >1.1G，回退方案=模型拆「完整版/精简版（仅 e5+reranker 717M）」两个包。
- **asar 内 MCP 失效**（换 electron 版本等）：回退形态 A（项目态码）为主，安装态改捆 node.exe 方案。
