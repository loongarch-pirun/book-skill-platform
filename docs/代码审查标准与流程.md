# 代码审查标准与流程

> 生效日期：2026-11-16　适用仓库：`book-skill-platform-r4`
> 一句话：**审查不是"再看一眼"，是补齐机器查不到的那部分。**
> 本文件是唯一标准。它不发明新流程，而是把这个仓库已经在做的事（防线包、存档照、台账、独立卷子）串成一条可执行的关。

---

## 1. 为什么要有它

这套代码不是没有纪律，而是**纪律散在各处**：防线包有 340 条静态断言、台账有八列、存档照有指纹链、卷子有 sha256、lint 有存量基线。缺的是「一个人改完，另一个人按同一张表核对」这一步。

最近三天真实发生过的四件事，正好是四类典型缺口：

| 事故 | 属于哪类缺口 | 对应的关 |
|---|---|---|
| 缓存写好了「代码里也有」，但根本没接到路由那条路上，白开一个开关 | 正确性：改了对的地方吗 | 关 3 |
| 文档写 reranker 是 fp32，代码是 int8、磁盘上也没有 fp32 权重 | 一致性：三处说法不同步 | 关 1 |
| 回归里 3 套红灯被当成「这次改坏了」，重新证了一遍才发现是存量 | 判据：分不清新增与存量 | 关 1 + 关 5 |
| 「动态配额能提速」被算出来只差 1 条，差点当成功劳写进报告 | 归因：把没发生的事写成收益 | 关 4 |

## 2. 三级分类：不是所有改动都要审

改动的风险不取决于行数，取决于**它能不能悄悄改变用户看到的结果**。

| 级别 | 什么改动 | 审查强度 |
|---|---|---|
| **A 轻** | 只改 `docs/*.md`、`README`、代码注释、`.gitignore` | 作者自查 + 跑 lint。**但凡是写进文档的事实性数字，必须能被命令复算** |
| **B 中** | `test/**`、`tools/**`、`build/*.ps1`、`package.json` 的 scripts | 另一人复核 + 跑该套件。新增断言必须能证明它「会红」（翻转验证） |
| **C 重** | `src/**` 生产码、`package.json` 的 `build` 段、`.db` 结构、判分尺子（`test/lib/judge.mjs`）、卷子（`test/holdout/**`） | **强制双人，作者不能自己批**。五关全跑 |

判定口径：拿不准就算 C。

## 3. 五道关（按顺序，能机器查的不让人盯）

### 关 1 · 机器闸门

```bash
npm run lint                      # 判据：改动文件 0 新增错误（存量 8 条见 lint-存量基线.md）
npm run test:ci                   # 18 套，不依赖真库与模型
node test/<相关套件>.mjs           # 改了哪块跑哪块
```

**必须回答一个问题：这次红的是不是我的？**
方法：把改动文件切回 `git HEAD` 复跑同一套。红数一样 → 存量；红数变多 → 你的。
（本项目已踩过一次，见 §1 第三行。）

### 关 2 · 静态契约

防线包 `node test/guard-test.mjs`（当前 340 项）不是可选项。审查时只看两件事：

1. **有没有新增断言覆盖这次的新风险**（新开关、新默认值、新执行顺序）；
2. **旧断言有没有被悄悄放宽**（删断言、改条件、`if: false`）。

> 反例：把 `scanBookSem` 里 `assertEngine` 挪到 `getMatrix` 之后，功能全绿、340 条也全绿——因为当时那条断言写成了「getMatrix 不存在也算过」。这类"看起来在守其实没守"的断言，审查时要专门挑出来。

### 关 3 · 人工审查（机器查不到的部分）

只审四类，别管风格（风格交给 lint）：

| 维度 | 问什么 |
|---|---|
| **正确性** | 改的是起作用的那一处吗？有没有"写了但没接上"？ |
| **契约** | 返回字段、参数语义、错误码有没有变？变了谁受影响？ |
| **数据与安全** | 会不会写坏 `.db`？有没有未校验的外部输入拼进 SQL/路径？删的东西能不能恢复？ |
| **可维护性** | 半年后的人能看懂"为什么这么改"吗？注释里的数字还能复算吗？ |

### 关 4 · 效果验收（涉及检索/打分/生成时强制）

- **独立卷子**（`test/holdout/sets/*.json`，sha256 冻结）判效果；
- **对照组差分**：同一张卷、两套代码各跑一遍，逐题比通过模式；
- **同源 80 题只能当回归门禁**（不许退化），**不许当"变好了"的证据**——自己批自己的卷不算。

### 关 5 · 留痕

| 动作 | 要求 |
|---|---|
| 台账 | `存档照/改动台账.md` 八列齐全，一行一改，**不许事后补** |
| 存档照 | 每次改动后 `node 存档照/生成清单.cjs <r4>` 重拍，记下新树指纹 |
| 指纹链 | 报告里写 `旧指纹 → 新指纹`，能一眼看出中间有没有无痕改动 |
| 卷子 | 冻结后只许看分，不许改题；改题必须新开 `setId` |

## 4. 本仓库专属红线（命中即 🔴 Blocker）

这 12 条不是通用教条，每一条都对应一次真实踩坑或一次侥幸。

| # | 红线 | 为什么 |
|---|---|---|
| 1 | 改 `routeAndSearch` / `hybridSearch` 的返回字段结构 | 4 个生产调用方 + 6 套测试靠它，破一处全套静默错位 |
| 2 | 把 `assertEngine` 挪到 `getMatrix` 之后 | 缓存只比引擎字符串，不校验库内维度，坏库会被"合法"读出垃圾分 |
| 3 | **静默调参**：改 `ROUTE_DEFAULTS`、质量基线、`clampMaxBooks` 上下界 | 调松一档没有任何报错，分数会慢慢失真。参数值必须由静态断言钉死 |
| 4 | 往 `test/golden/` 写一字节 | `golden.sha` 是回归门禁的锚，动了整条链失效 |
| 5 | 改已冻结卷子的题目/答案/sha | 等于考完改答案 |
| 6 | 在 clean / inline 链路 import 缓存清理 | 双进程写盘会打架，`guard-test` 有静态禁令 |
| 7 | 直接改 `.db` / 改 `chunks.id` / 重新切片而不写迁移 | 无迁移的库结构变更 = 数据不可回退 |
| 8 | 用同源 80 题证明"效果提升" | 判据混用，等于自己批自己的卷 |
| 9 | 改默认开关（缓存默认开、路由默认关）而不说明回滚方式 | 用户装上去就是新行为，出问题没有一键退路 |
| 10 | 无台账 / 未重拍存档照的改动 | 追溯链断掉，下一轮分不清存量与新增 |
| 11 | 新增第三方依赖 / 在 CI 加真库或模型依赖 | 包体已 1.8 GiB，CI 无模型；加一样就多一个不可控变量 |
| 12 | 删模型、删库、删 release 产物 | 不可逆（本项目出现过回收站被策略拦下、只能永久删除的情况） |

## 5. 审查意见怎么写

格式固定，一次给全，不分批：

```
🔴 Blocker · 契约：返回体少了 skipped_books
第 3 行：catch 分支改成 continue，skipped_books 不再 push。
为什么：MCP 端靠它告诉用户"哪本书没翻成"，少了就是静默降级。
建议：保留 push，或在 out 上加 route_skipped 新字段，别删旧字段。
```

- 🔴 **Blocker**：不改不许合（红线、契约、数据、安全）
- 🟡 **Suggestion**：这轮该改（命名、重复、缺测试、性能）
- 💭 **Nit**：可选（注释、排版）
- 提问题时先问意图，别假定是错的：「这里为什么用 N 而不是 N-1？我担心……」
- 好代码要点名：把巧妙的解法说出来，下次别人才知道那是对的

## 6. 角色与节奏

| 角色 | 谁 | 做什么 |
|---|---|---|
| 作者 | 改代码的人 | 交改动说明（`docs/审查模板-改动说明.md`）+ 跑完关 1/2 |
| 审查人 | C 类不能是作者本人 | 关 3/4，出意见，一次给全 |
| 留痕人 | 作者 | 关 5 |

节奏只定两条，不排具体时辰：
- 阻塞项当天回复；
- 同一 PR 不出现第三轮以上往返——两轮还没收敛，说明改动说明写得不合格，回去重写。

---

## 7. 度量（每月看一次，别天天看）

| 指标 | 怎么取 | 健康区间 |
|---|---|---|
| Blocker 密度 | 每月 Blocker 数 ÷ 合入改动数 | 下降即有效 |
| 回退率 | 合入后 7 天内被 revert/热修的比例 | 目标是 0 |
| 存量红灯误判次数 | 把存量红当新增红的次数 | 目标是 0（靠关 1 那句"是不是我的"） |
| 文档-代码不一致数 | `grep` 抽查关键字（如 fp32/700MB/e5） | 目标 0 |

## 8. 工具

```bash
# 看这次改动该跑哪几关、有没有漏台账
node tools/review-packet.mjs
```

它按 §2 分级、按 §3 列出必跑闸门，并检查 `存档照` 指纹是否需要重拍。**它只提醒，不代替判断。**
