## 二、架构：一套核心，四个壳

### 2.1 分层

```
┌──────────────────────────────────────────────────────────┐
│ 壳层（四种入口，共享同一核心）                             │
│  A. Electron 桌面   B. MCP stdio   C. 22 个 CLI   D. 安装包 │
└───────────────────────┬──────────────────────────────────┘
                        │ 全部只调 lib，不复制逻辑
┌───────────────────────▼──────────────────────────────────┐
│ src/lib/ —— 31 个纯能力模块（13 类能力）                    │
│  检索   search / keywords / vec-cache / similar / models   │
│  理解   catalog / enrich / enrich-signal / query-rewrite   │
│  加工   clean / inline-clean / semantic-chunk / structurize │
│  读写   browse / outline / lookup / assets / derived        │
│  技能   skill-store / skill-validate / skill-health         │
│  治理   usage-policy / skill-state / cite-check             │
└───────────────────────┬──────────────────────────────────┘
                        │
┌───────────────────────▼──────────────────────────────────┐
│ 数据层：SQLite（FTS5 + 向量 BLOB + 编目表）  18 个 .db       │
└──────────────────────────────────────────────────────────┘
```

**关键判断：这不是「一个 Electron 应用」，是「一个检索内核 + 四个壳」。**
`mcp-server.mjs` 只有 15 行——工具注册全在 `lib/register-tools.mjs`，桌面端和 MCP 端共用同一份注册逻辑。CLI 也是同一批 lib 函数。所以：改一处检索逻辑，桌面 / MCP / CLI 三端同步生效，不存在「三份实现漂移」。

### 2.2 七个值得单独点出的设计决策

**① 模型唯一入口（`lib/models.mjs`，111 行）**
换引擎只改一个文件。`assertEngine` 卫兵在读写两端拦截「库和查询不在同一向量空间」——宁可不答，不答错。这条防线在引擎烘焙大赛（43 题，三家引擎 × 有无复试官）后固化。

**② 目录解析三层 + 注入（env > 配置 > 默认）**
`currentLibDir()` / `currentSkillsDir()` 同款结构。桌面端把解析结果写进 `process.env`，spawn 的 CLI 子进程继承——迁库后 CLI 不瞎。
**这个设计有个真实教训**：安装态 MCP 复验时发现 `skill-store` 只认注入不认 env，导致 app.asar 里 7 个技能包全读不到。修复后补了 6 条断言。**静默契约漏洞只能靠解包真跑抓，静态审查抓不到。**

**③ lib 层不 throw（铁律）**
失败返回 `{ error, hint }`，唯一例外是 `CANCELLED`（用户取消必须穿层）。好处：调用方永远不用 try/catch 包业务调用，错误文案统一由 `humanizeError` 翻成人话。

**④ 进程内缓存带失效指纹（`listBooks`）**
缓存未过滤的全量清单，失效信号 = 文件名集合 + 每个 `.db` 的 mtime/size。`BSP_LIST_CACHE=0` 一键回退。返回浅拷贝，调用方改返回值污染不到缓存。有 `listCacheStats()` 观测钩子。

**⑤ 代际号防旧管线污染（`jobs.mjs`）**
「取消后立刻重导入 → 旧管线收尾删掉新条目」这类竞态，用 bookId 级 generation 计数器解决：旧管线每处 emit 都带启动时的代际号，不符一律落空。
**这是异步系统的经典难题，多数个人项目会直接踩，踩了也不知道。**

**⑥ 信号「提名制 + 地板阈值」**
编目/洗数据信号不给所有块加权，只做两件事：池内轻加权（0.3）、池外提名（人物 8 + 主题 4）保证进复试窗。低于 0.15 的信号直接无效化。
理由写在注释里：「高频人物（352 块都提达西）的命中是噪声，乱提名会挤掉凭实力进窗的答案块（实测把 pemberley 英文题从过打到漏）」。

**⑦ 双形态 MCP 的闸机豁免**
`registerServerTools(server, { gate })`——对外部智能体开闸机（定时窗/预算/开关），对自家验收测试传 `gate: false`。
**教训来源**：18:51 老板在桌面端关闸，stage3 测试全红。闸机治外部智能体，不治自家测试。

### 2.3 架构评分

| 维度 | 评价 |
|---|---|
| 分层清晰度 | 优。四壳一核，边界靠「只调 lib 不复制」这条纪律维持 |
| 依赖方向 | 单向。renderer → preload → ipc → engine → lib，无反向依赖 |
| 可替换性 | 优。模型/目录/存储三处都是单点可换 |
| 抽象过度 | 无。31 个模块，最大的 831 行，没有为了抽象而抽象的空壳层 |
| 循环依赖 | 零（`engine.mjs` 被 `jobs.mjs` 引用 `UserError`，是唯一的主进程内部依赖） |

### 4.1 规划体系

## 五、代码抽查：具体好在哪

### 5.1 注释写「为什么」，不写「做什么」

```js
// P5 进程内缓存：缓存未过滤的全量清单（按 libDir 分桶）——includeDisabled 过滤在缓存
// 之上现读 skill-state（轻 json），skill-state 变化天然不触发清单失效。失效信号两个：
// .db 文件名集合变化 + 任一 .db 的 mtime/size 变化...
```

这类注释在项目里是常态。每段都带：设计动机、失效条件、回退开关、踩过的坑。**读者不需要问「为什么这么写」，作者已经预先回答了。**

### 5.2 防御性设计到位但不啰嗦

```js
const RECALL = Math.min(Math.max(topN * 4, 12), 20) + ((cat.hit.size || enr.hit.size) ? 8 : 0);
```
上界下界都夹住，注释解释「为什么扩 8 席：证据块常排在 20 名开外」。

```js
db.prepare(`... WHERE text LIKE ? ESCAPE '\\'`).all(`%${q.replace(/[\\%_]/g, "\\$&")}%`)
```
LIKE 通配符转义——`100%` 不会匹配半本书。

### 5.3 文件系统级防御

- 大小写不敏感探测（`fsCaseInsensitive`）：win32/macOS 上 `book.docx` 与 `Book.docx` 会静默覆盖，探测失败按「不敏感」处理（fail-safe，因为这是数据丢失级闸门）。
- 句柄泄漏防御：坏库路径先 `close()` 再过滤，注释写明「Windows 上泄漏会让删库报 EBUSY」。
- 原子写：技能保存用临时目录 + rename，`.tmp-*` 僵尸目录会被清理。

### 5.4 测试不是「测复制品」

```js
// 复制一份真库到临时目录（只读实验永远不动真库）
const copyDb = (src) => { ... };
...
ok(threw && /引擎不一致/.test(threw.message), "卫兵: meta.model 标记不匹配被拒");
ok(threw && /重灌|BSP_EMBED_MODEL/.test(threw.message), "卫兵: 报错信息带修复路径");
```

直接调真实实现，在临时目录做破坏性实验，并且**断言错误消息里带修复路径**——测的是「用户能不能自己解决」，不只是「函数有没有抛错」。

## 六、真实短板（不客气）

### 6.1 没有类型系统（最严重）

13,867 行纯 JS，零 JSDoc 类型标注，零 `checkJs`。
**后果**：改一个字段名，编译器帮不了你，只能靠 1,367 个断言碰运气命中。断言覆盖的是「跑过的路径」，不是「所有引用点」。
**成本估计**：加 JSDoc + `// @ts-check` 是低成本高收益，不需要迁 TS，`tsc --noEmit` 就能查出大半拼写/签名错误。

### 6.2 单文件偏大

| 文件 | 行数 | 判断 |
|---|---|---|
| `lib/catalog.mjs` | 831 | 编目全流程塞一个文件：聚类/任务书/解析/导入/查询/图谱扩展 |
| `build-book.js` | 768 | 四格式解析 + 切片 + 落库 |
| `desktop/engine.mjs` | 650 | 38 个导出函数，桌面能力门面 |

注释清晰所以「读得懂」，但**改的时候要在 831 行里找落点**。catalog 至少能拆成 `catalog-core` / `catalog-task` / `catalog-import` / `catalog-query` 四个。

### 6.3 无覆盖率门禁

1,367 个断言听起来多，但**断言数 ≠ 分支覆盖率**。
现在无法回答：「`clean.mjs` 的哪几个分支从没被执行过？」
加 `c8` 或 `node --experimental-test-coverage` 就能出数，成本很低。

### 6.4 无性能门禁

延迟只记录（`avgLatencyMs: 3323`）不拦截。检索代码改慢 3 倍，测试照样全绿。
建议：金卷跑分时同时断言 P50 延迟上限（比如 6 秒），超了红。

### 6.5 Electron 没上锁

```js
webPreferences: { preload: path.join(__dirname, "preload.js") }
```

`contextIsolation: true` / `nodeIntegration: false` 靠 Electron 默认值（44.x 默认安全），没有显式声明，也没有 CSP meta。
**实际风险低**（纯本地 file:// 页面、不加载远程内容、XSS 纪律到位），但这是「没出事」不是「上了锁」。补两行 + 一个 meta 标签的事。

### 6.6 错误处理有 75 个「无注释 catch」

131 个 catch 中 56 个带注释说明为什么吞，75 个没有。
不是 bug，但排查线上问题时，这 75 处是盲区。

### 6.7 单人知识集中

6,406 行文档 + memory 是唯一的外部记忆。**没有第二个人能接这个项目**——不是代码难，是上下文太多（18 本书的编目特性、125 题金卷的漏题原因、六条检索腿的开关矩阵）。

交接文档解决了「怎么用」，没解决「怎么改」。

| 质量度量 | 「能跑」 | 「测试绿」 | **125 题金卷 + 漏题清单 + 238 项静态断言** |
| 发布 | 源码 | GitHub Release | **701MB 安装包 + 首启向导 + 种子化** |
| 技术债管理 | 无记录 | issue 列表 | **9 项登记在案 + 5 commit 瘦身 + 前后实测数** |

### 7.2 判断

**工程完整度：前 1%。**
理由不是任何一个单项特别强，而是**七项同时达标**：架构、测试、文档、发布、度量、技术债、复盘。个人项目通常死在「没有验收标准」——写完了自己觉得行就发布。这个项目每一波都有「怎么算做完」的定义，而且是机器可验的。

**技术难度：中上，不是顶尖。**
手搓 RAG 不难，难的是「知道自己的检索到底行不行」——125 题金卷 + 双门（分数 + 漏题清单）+ 复试官消融实验，这套度量体系比多数公司的 RAG 项目规范。但没有分布式、高并发、大规模数据这些硬骨头，所以是「深度够、广度中等」。

**可复制性：这才是真正的价值。**
这套流程（定方向 → 写规划含验收标准 → 实施 → 测试同步 → 全量门禁 → 回写偏差）不依赖任何天赋，任何人照着做都能提升一个档次。**项目最大的产出不是软件，是这套方法论。**

### 7.3 一个必须说清的背景

代码是 AI 写的，老板负责定方向、拍板、验收、记账。
所以这个项目的水平，准确表述是：**「一个产品负责人 + AI 施工队」能达到的工程上限样本**。
它证明的不是「AI 会写代码」，而是「有人把验收标准定死之后，AI 能稳定产出工业级质量」。反过来说：**没有验收标准的 AI 编程，产出的是能跑但没人敢改的代码。**

## 八、如果继续做：优先级
