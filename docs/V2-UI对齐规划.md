> 范围：V2 P1~P3 新增能力（云端配置 / 云端总结 / 对话窗口）与阶段 4 五视图既有体系的界面一致性

## 一、结论

**能对齐，而且大部分已经对齐。** V2 的新功能是"寄生"在既有设计体系上长出来的，没有另起炉灶。真正要处理的是：

- **4 个到手就会撞上的硬伤**（A 档，其中第 2 条正是当前真机试对话的第一道坎）
- **6 个一致性小漂移**（B 档）
- **5 个可选项**（C 档，等发话）

按 A → B → C 三批走，每批都是加法、可单独回滚。

- 读全部渲染层：`app.js` / `views.js` / `views-reader.js` / `views-ask.js` / `views-chat.js` / `app.css` / `index.html`

## 四、问题清单

### A 档：真机试对话当场会撞上（必修 4 条）

**A1 对话页回答失败时，一段原文都看不到**
- 证据：llm.mjs:181/184 降级文案承诺"已降级为原文片段"；views-chat.js:94-96 只 push 一个 error 气泡——本地已检索到的 6 段原文没有任何展示路径。问一问页反而天然降级（本地结果一直在下方，views-ask.js:46）。
- 现象：模型偶发抽风（QUOTE_FAIL/BADRESP）时，对话页只剩一句红字，用户想自己核对原文，还得去问一问页把问题重问一遍。
- 方向：chat.mjs:60 失败时把已检索到的 results 一并返回（degraded 标记），对话页 error 气泡下挂"本地原文"折叠区。llm.mjs 不动。

**A2 书全关时，两页只说"（没有可问的书）"，不告诉人去哪开**
- 证据：views-ask.js:11 / views-chat.js:12。
- 现象：当前 7 本书 skill 全关，打开对话页第一眼就是这个空下拉，没有任何"去开书"引导——正是这轮真机测试的第一道坎。
- 方向：空态加"去「技能开关」打开"按钮（`show("skills")`），两页同加。

**A3 同一个云端错误，两种寿命**
- 证据：问一问页 toast 3.2 秒一闪而过（views-ask.js:274）；对话页是持久 err 气泡（views-chat.js:95）。
- 现象："API key 无效"这种要用户去处理的信息，在问一问页可能没看清就消失了；对话页又过于隆重。同一错误两种人格。
- 方向：问一问页的云端错误改内嵌错误条（持久、可复制），toast 只留"已保存"类轻通知。

**A4 对话页不交代"答案取材自哪里"**
- 证据：问一问页有 routed-note（views-ask.js:42，全库模式显示翻了哪几本书）；chat.mjs:61 已返回 mode/book，但 views-chat.js 的 msgHtml 不渲染。
- 现象：全库模式问一个问题，用户不知道答案翻的是哪本书——与"引用可核对"的产品定位不符。
- 方向：AI 气泡下加 meta 行：`取材 N 段 · 来自《X》`（全库时列书名）。

### B 档：一致性漂移（应修 6 条）

**B1 同一个问题，两页喂给云端的原文段数不同**
- 证据：views-ask.js:133（topN 4）vs views-chat.js:88（topN 6）vs views-ask.js:270（topN 6）。
- 现象：同一本书同一个问题，问一问页给云端 4 段、对话页给 6 段——答案质量不可比。
- 方向：抽共享常量（云端总结固定 6），两页引用同一处。

**B2 输入区规格与文案口吻两套**
- 证据：app.css:126（ask 页 textarea 固定 56px）vs app.css:263（chat 页 min56/max140 自适应）；placeholder"输入问题，回车提交"vs"问吧——比如…"；加载文案"引擎检索中（平均约 3 秒）"vs"正在检索书库并写作（约几秒）"。
- 方向：输入框规格统一（尺寸/自适应/focus 态）；文案定一张表，一次定死。

**B3 云端区配色没吃变量**
- 证据：app.css:229-240 硬编码 `#fffdf7`/`#fffefb`/`#eadfc2`；AI 总结区底 `#fdfaf1` vs 对话气泡底 `#faf6ea`——两个"AI 产物区"两个底色。
- 方向：新增 `--ai-bg`/`--ai-line` 变量统一收编，未来换肤只改变量。

**B4 注释与命名漂移**
- 证据：app.js:2 注释还写"四个视图"（实际五个）、app.js:12 view 注释缺 chat；IPC 两种命名风格并存（`books:list` 名词式 vs `llm:configGet` 动宾驼峰，ipc.mjs:49-52）；preload 暴露名混（`ask` vs `chatSummary`，preload.js:26-31）。
- 方向：注释更新（零风险）；新通道命名规范写进文档，老通道不改名（冒烟脚本在咬）。

**B5 顶栏全局搜索语义过时**
- 证据：index.html:14 placeholder"一次搜遍所有书，回车直接问（全库模式）"——V2 之后"问"有歧义（本地检索？云端对话？），且它只走 ask 页。
- 方向：文案改清（"回车本地检索"）；"云端对话"直链放 C 档评估。

**B6 换书不换技能包**
- 证据：views-chat.js:80——skillSlug 只在勾选时读取，切书不清；问 A 书可能挂着 B 书的技能包当"辅助理解"。
- 说明：引用校验只认 results，所以出不了假引用——属整洁性问题，不出安全问题。
- 方向：切书/切模式时清 skillSlug（或按技能包 sources 校验匹配）。

## 五、对齐规划（三批，全部加法）

### 第一批 A（必修，一轮内做完）

| 步骤 | 文件 | 动作 | 风险 |
|---|---|---|---|
| A2 | views-ask.js / views-chat.js | 空态加"去开书"按钮（加行 + 复用 `show`） | 零 |
| A1 | chat.mjs / views-chat.js | `cloudSummary` 失败返回 `results + degraded`；err 气泡挂本地原文折叠区 | 中（改返回结构；UI 只加读字段，llm.mjs 不动） |
| A3 | views-ask.js / app.css | 云端错误改内嵌条（新增 `.clouderr`） | 低 |
| A4 | views-chat.js | AI 气泡加 meta 取材行（chat.mjs:61 数据已在手） | 零 |

真机验收点：①全关时有点按钮能跳能开 ②断网/错 key 能看到本地原文 ③全库问答显示取材。

### 第二批 B（一致性，一批做完）

- B1 topN 常量共享；B2 输入规格 + 文案表；B3 配色变量收编；B4 注释更新；B5 顶栏文案；B6 切书清 skillSlug。
- 每项都是加行/换字级；renderer-graph-test 补对应断言（空态按钮、meta 行、topN 常量）。

### 第三批 C（等发话）

- C1~C5 逐项评估，其中 C3 并入 P4。

## 六、边界（对齐规划同样守 V2 八条硬规矩）

1. 检索层 / 引擎 / MCP 一行不动（ask() 同一条路继续复用）
2. IPC 老通道不改名不删（冒烟脚本与 MCP 都在咬）
3. 每步独立提交、可单独回滚
4. 零新依赖
5. 文案表定稿后再动字（一次把口吻定死，避免二次漂移）
