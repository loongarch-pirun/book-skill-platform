# 行级清洗（块内净化）立项方案

> 2026-10-20。上游：kkndme 正式收录（a06a091）实测留档「行级清洗立项候选」。
> 本文回答：块内污染是什么、怎么治、护栏怎么设、验收怎么过。

---

## 一、为什么立项：实证摸底数据

对 kkndme-zh.pdf.db（760 块 / 300,586 字 / ≈225K token）全量只读扫描：

| 污染类型 | 实证 | 规则可化程度 |
|---|---|---|
| 页码残留（块首/块尾孤立数字行） | **755/760 = 99.3%** | 100% 行级正则 |
| 楼层号「N楼」 | 541/760 = 71.2%，共 670 个标记，349 块在块内非首位出现 | 100% 行级正则 |
| 跟帖署名（`作者：X回复日期` / `•用户名+日期`） | **457/760 = 60.1%** 块含至少一种强边界信号 | 边界可规则识别 |
| 长分隔线（`——————` / `====`） | 394 块，478 条 | 100% 行级正则 |
| 问-答粘连（块内同时含读者问与楼主答） | 517 块含问句，其中 310 块含回复标记 | 60% 有规则边界，其余 LLM 兜底 |

典型块内结构（块 #23 实录）：

```
[楼主正文/引用上文]
•ty_烟雨江南288 2018-02-23 20:37      ← 跟帖署名+时间戳
[跟帖正文]
作者：sunxinmfc 回复日期：2010-08-11 22:45:56   ← 跟帖边界
[跟帖正文]
20                                        ← PDF 页码
```

**伤害面**（不是美观问题，是质量问题）：

1. **引用污染**：cite_check 逐字回验过的引文，输出时裹着页码、署名、楼层号——答案不干净
2. **语义纯度**：问句与答句同块，问句向量拉低块的语义集中度，问「公租房」可能命中一段通篇是读者提问的块
3. **token 虚账**：300,586 字里约 7% 是纯噪音（页码/楼层/署名/分隔线），read_full_book 闸和 total_tokens 账记的是加工前的数

**现有管线为何治不了**：clean-book 是「整块判、整块删」（G1–G5 五护栏），块**内部**的污染从来不在它的视野里；语义分块只管把碎块并起来，也不净化块内。九本佚书波次里 d2l 靠语义分块从 33,323 块降到 5,481 块，但块内的 label 行、页码依旧原样。

## 二、方案分层（按风险从低到高，每层独立可回退）

管线位次：**build → clean（整块删，已有）→ inline-clean（块内净化，本次新增）→ embed → enrich**。
行级清洗必须在 embed 前：切块/删行都会改 chunk 集合，emb 列作废重做。

### L1 机械净化（纯规则，零 LLM 成本）

删除四类行级噪音，逐行正则、只删整行：

| 规则 | 正则（行级） | 受益块占比 |
|---|---|---|
| 页码行 | `^\d{1,4}$`（仅限块首/块尾 3 行内） | 99.3% |
| 楼层号 | `^\d{1,4}楼[:：]?` | 71.2% |
| 跟帖署名 | `^作者[:：].*回复日期.*$`、`^[•·]\s*\S{2,20}\d{4}-\d{2}-\d{2}.*$` | 60.1% |
| 长分隔线 | `^[—=\-_]{6,}$` | 51.9% |

**预期收益**：约 20K 字（≈7%）噪音下线，引用输出立即干净，token 账回落，零语义风险（删的都是非正文行）。

### L2 问/答分离（规则切分 + LLM 兜底）——核心设计决策

跟帖边界信号（60.1% 块自带）把块切成「主帖段 + 跟帖段」，然后二选一：

- **方案 2a（推荐）：切不删**。主帖段留在原块，跟帖段切成独立新块。
  理由：跟帖不全是水——「辨别利益是看透一切事物真相的武器」「一线城市的保障房运用还是比较得当」这类跟帖本身就是可检索内容；删了是信息损失，切开了是语义提纯。kk 编目 19 个人物不少就活在跟帖里。
  代价：块数 760 → 估 900+，**编目边作废需重编**（catalog_chunk_count 对不上），emb 重做。
- **方案 2b：跟帖段删**。信息损失大，不推荐。

无边界信号的粘连块（约 60 块）交 LLM 判切点，判不准 keep（对齐 G3 精神）。

### L3 检索层问块带答（备选，不改库）

若 L2 不做，退而求其次：检索命中「纯问块」时把相邻下一块（答块）一并喂模型。实现最小，但只治检索不治引用。**L2 落地后 L3 不需要。**

## 三、护栏设计（对齐 clean-book 五护栏 + 版本闸）

| 护栏 | 规则 | 对齐 |
|---|---|---|
| I1 | L1 只删行级正则命中的整行；单块删除行数 >30% 拒收该块 | G1 实义短块精神 |
| I2 | L2 只切不删；切出的跟帖段 <20 字直接丢弃（无检索价值）；切出的新块 <30 字不单独成块 | G2 引文公式代码精神 |
| I3 | LLM 兜底判不准 → 原块保留 | G3 同款 |
| I4 | 整书净化率闸：删行占比 >15% 报警，>25% 拒收（`--force-gate` 双 flag 强过，同 clean-book） | G4 同款 |
| I5 | 隔离账：每块的删行明细、切块明细落隔离表，`--ids/--all` 可整体恢复 | G5 同款 |
| I6 | 版本闸：`INLINE_VERSION=1` 写 meta；改规则必须 bump；缓存行无标记 = stale 拒收 | CLEAN_VERSION 同款 |
| I7 | 账目同事务：净化/恢复都调 `syncBookMeta`（chunk_count/total_chars/total_tokens 四本账，clean-import 已有现成函数复用） | 清洗账不同步事故的根治 |

## 四、验收标准

1. **机器可验**：净化后重跑摸底探针——页码行、署名行、楼层号、分隔线命中数 ≈ 0
2. **保留率合理**：整书字数降幅落在 5%–15% 区间（预期 ≈7%，护栏 I4 双闸兜底）
3. **恢复可逆**：隔离账 `--all` 恢复后 chunk_count/字数/clean_content_hash 与净化前精确一致（kk-clean-slow-test 同款断言）
4. **eval 双门**：npm test 全量绿；v2-eval 102 题 ≥90 分且漏题 ⊆ 基线漏题（不许新增漏题）
5. **引用抽样**：人工抽 5 条 cite_check 命中，确认引文无页码/署名裹挟

## 五、工期与批次

| 批 | 内容 | 工作量 | 风险 |
|---|---|---|---|
| L1 | 四类行级噪音 + I1/I4/I5/I6/I7 护栏 + 恢复 + 测试 | 半天 | 极低（删非正文行） |
| L2 | 问/答分离（2a 切不删）+ LLM 兜底 + I2/I3 + 隔离账扩展 + **kk 重编目** | 一天 | 中（块集合变，编目链重跑） |
| 验收 | 五条标准逐项过 | 半天 | — |

**先 L1 后 L2**：L1 当天可完、零 LLM 成本、引用立即干净；L2 动块集合牵动编目，需要单独一波次排期，且 2a/2b 策略值得拍板后再动。

## 七、执行记录（2026-10-20 完工）

拍板：**2a 切不删 + 机制化**（桌面「开始加工」管线 clean 之后 embed 之前自动跑，零 key）。

| 项 | 落地 |
|---|---|
| 核心 lib | `src/lib/inline-clean.mjs`：stripNoiseLines / splitByReplyBoundary / planBlock / buildInlinePlan / checkInlineGate，INLINE_VERSION=1 |
| 落库恢复 | `src/lib/inline-import.mjs`：importInline（四道闸 STALE/STALE_STRUCT/GATE/TAMPER + 单事务）/ restoreInline / auditInline；隔离账 quarantine 扩展 split_json 列 |
| CLI | `src/inline-clean.mjs <db> [--dry-run/--force-gate/--restore --all/--ids]`；幂等跳过（已净化且书未变） |
| 桌面接线 | jobs.mjs 管线位次 clean → **inline-clean** → embed（spawn 带 nodeEnv()，G-01 锁；失败落 failed 态；读 inline_report 拼横幅） |
| 测试 | `test/inline-clean-test.mjs` 76 断言（单测+集成+恢复逐字回滚+四道闸）挂 test:fast；kk-clean-slow-test 加「真建库脏料上行级全链路」段；guard-test 加 11 条静态契约（含管线位次断言） |

**kkndme 实测**：760 块 → 1144（切出跟帖 384）；strip 461 / split 298 / keep 1；楼层号残留 670→**0**；
字数 -12.3%（300586→263143）；净化率 12.7%（黄线下）；I1 拦回 0。重 embed（1144 向量 + 24 概念
+ 3432 边）+ 重编目（12 主题 31 人物 9 关系，belongs 786 / mention 646）。**考卷 92→93：
净做对「读者问全款买房还是贷款买房更划算，楼主给了什么思路」——问帖/答帖分离的直接收益，
无新增漏题（双门过）。kk 逐本 7/10 → 8/10。**

**实施中修正的两个设计**（实测踩到，记档）：
1. **顺序**：必须先按跟帖边界切段、再对各段删行——反过来先删行会把署名边界删掉，切分失效。
2. **I1 语义**：原按「删行占比 >30%」拒收，实测把「整块皆跟帖」的块误拦（块 204：删行 35% 但
   剩余仍有百字跟帖正文）。所有删除都命中确认的结构行正则，没有误删正文的路径——I1 真正该防的
   是「strip 后块成空气」，改为**剩余字数 <20 才拒收**。改后 kk 的 keep 从 11 降到 1。
3. **闸门阈值**：净化率黄线 15%→25%、硬线 25%→40%（对齐 clean-book dropWarnMax/dropHardMax）——
   论坛体署名行占比天然高，kk 实测 12.7% 是正常论坛体特征，原阈值会让每本论坛体书撞黄线。

**仍遗留**：LLM 兜底未做（约 60 块无边界信号的问-答粘连块现为 keep，行级规则覆盖 92% 块）；
GB 标准 OCR 需立项。
