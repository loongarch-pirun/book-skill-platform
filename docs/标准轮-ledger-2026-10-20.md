## 三、执行步骤（3 段，每段独立交证据）

### 段 1：静态分级审查（2-3 小时）→ 产出缺陷清单

1. 读 2.1 的 5 个模块全文 + 2.2 的 R1-R5 定向扫
2. 每发现一个问题，登记到「四、缺陷清单」：`ID | 文件:行号 | 描述 | 级别 | 理由`
3. 判级严格对照 skill 第五节表；**拿不准往重一级靠**
4. 疑点（读代码无法确认的）登记到「五、疑点清单」，随后逐条核验归类或挂起
5. 段末给一张**按级别汇总表**（致命 N / 严重 N / 一般 N / 轻微 N）

### 段 2：分组修复（1-2 小时）→ 一组一 commit

- 只修**致命 + 严重**；一般/轻微登记「遗留」不修（避免范围失控）
- 按契约域分组：`R1 错误处理` / `R2 管线状态机` / `R3 路径` / `R4 渲染` / `R5 连接`
- 每组一个 commit，message 里带缺陷 ID；改完立刻跑对应模块的针对性测试
- **每组修复后都要重跑 `npm run lint`**（今日教训：只 lint 改动文件会漏）

### 段 3：门禁收口 + 台账归档（1-1.5 小时）

| ② 全套回归 | `npm test`（fast 1809 + slow + eval-gate） | exit 0 | 完整输出（PASS/FAIL 计数） |
